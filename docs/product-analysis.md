# Продуктовый анализ

Planning Poker  |  Что делаем по спринтам  |  рабочая актуализация • 3 ноября 2026

Документ фиксирует функциональное наполнение проекта: что должно работать, какого результата ожидаем от каждого спринта, какие границы установлены и что допустимо перенести. Технические способы реализации, архитектуру, API, структуру БД и правила организации командной работы этот документ не предписывает.

Основа: «Продуктовый анализ» (версия 3 от 15.10.2026). Изменения 03.11.2026 ограничены подтверждёнными продуктовыми решениями. Предлагаемые сроки, объём и открытые вопросы требуют согласования PM/PO и команды.

## 1. Принцип наполнения спринтов

Каждая функция имеет целевой уровень: L1 — интерфейсный контур без обязательной бизнес-логики; L2 — минимально работающая функция на реальных данных; L3 — расширения и устойчивость уже работающего сценария. Для обязательного звена вертикального среза L1-заглушки недостаточно.

У задач есть признак переноса: «Нет» — перенос требует пересмотреть цель спринта; «Да» — допустим без нарушения его основного результата. Ожидаемые результаты и границы ниже определяют продукт, а не способ написания кода.

## 2. Спринт инициализации — завершённый этап

PRE-01–PRE-06 — задачи прежнего подготовительного этапа, материалы которого уже сохранены в репозитории. Они не переносятся автоматически в следующий спринт как новые требования. Имеющиеся технические схемы и спецификации допускается использовать как примеры возможной реализации. Фактический статус отдельных подготовительных работ учитывается в трекере команды.

## 3. Спринт 1 — «Скелет продукта»

**Цель.** Один Host проходит рабочий серверный путь: создание сессии → CSV-импорт с разметкой колонок и предпросмотром → очередь → выбор SP → подтверждение итогового SP → сохранённые результаты.

Обязательные шаги должны работать на клиенте и сервере; визуальные области будущих функций могут оставаться неактивными.

### S1-01 · Создание сессии и переход ведущего в лобби (L2)

**Ожидаемый результат.** L2: Host создаёт сессию через интерфейс, получает идентификатор, сформированный сервером, и попадает в лобби с данными этой сессии. По идентификатору серверную сессию можно получить повторно.

**Граница.** Создание и просмотр лобби ведущего; подключение других участников по коду не входит.

**Перенос.** Нет — входная точка обязательного пользовательского пути.

### S1-02 · Импорт задач из CSV с предпросмотром и подтверждением (L2)

**Ожидаемый результат.** L2: Host загружает один реальный CSV-файл, самостоятельно определяет назначение колонок, видит результат проверки всех строк и предпросмотр корректных задач. После подтверждения импортируются все корректные строки в серверную очередь; некорректные показываются с номером строки и причиной ошибки. Отмена не изменяет очередь.

**Граница.** Обязательно указать колонки для ID задачи, заголовка и будущей записи итоговых SP. Описание, ссылка YouTrack и дополнительные характеристики необязательны; названия колонок произвольны. Старые значения колонки итоговых SP игнорируются. Если в CSV нет колонки для итоговых SP, пользователь вручную добавляет такую колонку в конец файла и загружает CSV повторно; приложение показывает подсказку, но не создаёт колонку самостоятельно. Предупреждаем о будущей замене старых значений. Без Excel, прямого YouTrack API, редактирования строк в предпросмотре или импорта второго файла.

**Перенос.** Нет — без настоящего импорта задача спринта не достигнута.

### S1-03 · Просмотр очереди импортированных задач (L2)

**Ожидаемый результат.** L2: В лобби Host видит актуальный список задач, действительно импортированных в сессию, и может перейти к их оценке.

**Граница.** Очередь только для просмотра: без добавления, удаления, перестановки и пропуска задач.

**Перенос.** Нет — нужен переход от импорта к оценке.

### S1-04 · Просмотр текущей задачи и выбор SP ведущим (L2)

**Ожидаемый результат.** L2: Host видит сведения текущей задачи из серверной очереди и может выбрать числовую карту SP из набора.

**Граница.** Один голос Host; без голосов Participant, таймера, специальных карт и реальных подсказок эталонов.

**Перенос.** Нет — необходимая часть оценки.

### S1-05 · Фиксация итогового SP и переход к следующей задаче (L2)

**Ожидаемый результат.** L2: Host подтверждает окончательное числовое SP для текущей задачи; результат сохраняется на сервере и отображается после перезагрузки. Затем можно перейти к следующей задаче и повторить оценку.

**Граница.** Только один Host. Выбор карты до подтверждения — локальное состояние; после подтверждения значение должно быть сохранено сервером. Без участников, таймера, пересчёта голосов, переголосования и расширенной статистики.

**Перенос.** Нет — выбор карты без сохранённого результата недостаточен.

### S1-06 · Получение итогов сессии (L2)

**Ожидаемый результат.** L2: После оценки списка Host видит на экране результаты по задачам с реально сохранёнными итоговыми SP. Показатели, не применимые к одиночной оценке, отображаются прочерками.

**Граница.** Просмотр результатов без экспорта CSV, расширенной многопользовательской статистики и YouTrack.

**Перенос.** Нет — итоги завершают однопользовательский сценарий.

### S1-07 · Восстановление состояния и обработка базовых ошибок (L2)

**Ожидаемый результат.** L2: Перезагрузка страницы не уничтожает серверную сессию, импортированную очередь и подтверждённые итоговые SP. Основные операции при ошибке дают пользователю понятную обратную связь.

**Граница.** Базовые сбои текущего пути; детальная UX-полировка и редкие исключения могут выполняться позднее.

**Перенос.** Нет — в части сохранности и работоспособности основного сценария.

### S1-08 · Визуальные области функций следующих итераций (L1)

**Ожидаемый результат.** L1: При необходимости в основных экранах подготовлены визуальные области участников, исторических подсказок, таймера, комментариев и управления очередью. Неработающие элементы скрыты или явно неактивны.

**Граница.** Только визуальные элементы, без имитации настоящей логики и без реализации функций L2.

**Перенос.** Да — каркасы будущих возможностей не блокируют рабочий путь Host.

**Результат спринта:** Host самостоятельно создаёт сессию, импортирует задачи из произвольного поддерживаемого CSV через разметку, оценивает задачи и получает реальные сохранённые итоги.

## 4. Спринт 2 — «Многопользовательская оценка»

**Цель.** Host и Participant участвуют в одной сессии, голосуют, видят общий актуальный результат; итоговый SP утверждает Host.

### S2-01 · Подключение участника и разграничение ролей (L2)

**Ожидаемый результат.** L2: Participant входит в существующую сессию по коду или ссылке, видит актуальные данные и использует свой интерфейс без полномочий Host.

**Граница.** Минимальное подключение и рабочий интерфейс участника.

**Перенос.** Нет — определяет цель мультиплеера.

### S2-02 · Синхронное голосование нескольких участников (L2)

**Ожидаемый результат.** L2: Участники в одной серверной сессии отправляют голоса по текущей задаче, состояние синхронизируется между клиентами; Host завершает базовое голосование и самостоятельно фиксирует окончательный SP за задачей.

**Граница.** Голос каждого участника — временное значение раунда, подтверждённый итоговый SP — отдельный результат задачи. Важный для восстановления голос должен быть отправлен на сервер после подтверждения выбора; без таймера, повторных голосований и расширенной истории раундов.

**Перенос.** Нет — основное назначение спринта.

### S2-03 · Базовая статистика и восстановление соединения (L2)

**Ожидаемый результат.** L2: После голосования доступны рассчитанные по реальным числовым голосам основные показатели; после обновления или переподключения участник возвращается к актуальному состоянию сессии.

**Граница.** Минимальная статистика и сохранность общего состояния; сложные исключения позже.

**Перенос.** Да, отдельные расширения можно перенести, сохранив согласованный минимальный многопользовательский путь.

### S2-04 · Завершить исследование поиска исторических эталонов (—)

**Ожидаемый результат.** Сравнены подходы к поиску на полученных исторических данных, проверена релевантность и описан выбранный вариант реализации.

**Граница.** Исследовательский результат, не пользовательский поиск.

**Перенос.** Нет — исследование должно завершиться до начала L2-поиска в следующей итерации.

## 5. Спринт 3 — «Управление задачами и эталоны»

**Цель.** Host может управлять очередью и продолжать сессию; команда видит исторические подсказки, а участники могут комментировать задачи.

### S3-01 · Добавление задач и управление очередью (L2)

**Ожидаемый результат.** L2: Host может добавить задачу до или во время сессии, изменять очередь в предусмотренных пределах и пропускать текущую задачу с возвратом в конец очереди. Данные одинаковы для всех участников.

**Граница.** Набор операций и исключения описывает аналитик; без дополнительных форматов импорта.

**Перенос.** Нет — основное развитие управляемой сессии.

### S3-02 · Комментарии к оценке задачи (L2)

**Ожидаемый результат.** L2: Пользователи оставляют комментарии в контексте задачи; сообщения сохраняются и видны в сессии.

**Граница.** Комментарии по задаче, без отдельной расширенной системы общения.

**Перенос.** Да — если команда выделит обсуждение без текстовых комментариев как достаточный промежуточный результат.

### S3-03 · Поиск похожих задач из истории (L2)

**Ожидаемый результат.** L2: Для оцениваемой задачи отображаются реальные похожие эталоны (ориентир: 3–5) с исходными SP и ссылками. Подсказки не заменяют выбор команды.

**Граница.** Рабочий поиск по предоставленным данным; дополнительные улучшения релевантности относятся к L3.

**Перенос.** Нет — при сохранении цели спринта, включающей эталоны.

### S3-04 · Продолжение сессии после оценки всей очереди (L2)

**Ожидаемый результат.** L2: После последней задачи Host может перейти к результатам либо продолжить сессию добавлением задач в рамках предусмотренного сценария.

**Граница.** Без дополнительных сценариев управления завершёнными сессиями.

**Перенос.** Да — если сохранён путь к корректному завершению и итогам.

## 6. Спринт 4 — «Расширенный процесс голосования»

**Цель.** Раунд поддерживает таймер, предусмотренные варианты завершения, дополнительные карты и переголосование.

### S4-01 · Таймер и продление раунда (L2)

**Ожидаемый результат.** L2: У всех клиентов отображается общий серверный отсчёт; Host может продлить раунд на две минуты не более двух раз за сессию.

**Граница.** Без расширенных настроек расписаний и пользовательских напоминаний.

**Перенос.** Нет — при сохранении цели спринта.

### S4-02 · Досрочное завершение и дополнительные правила окончания голосования (L2)

**Ожидаемый результат.** L2: Завершение работает при получении всех голосов, истечении таймера или раннем решении Host при наличии хотя бы одного голоса; итоговое подтверждение остаётся за Host.

**Граница.** Точные исключения и статусы по аналитической спецификации.

**Перенос.** Нет — часть расширенного раунда.

### S4-03 · Специальные карты и переголосование (L2)

**Ожидаемый результат.** L2: Участники используют согласованные специальные карты и могут повторно проголосовать по текущей задаче; Host утверждает один итоговый SP, закреплённый за задачей.

**Граница.** Не требуется сохранять подробную историю голосов и состояний всех прошедших раундов ради расширенной статистики. Подробные правила сброса временных голосов при переголосовании уточняются в требованиях к раунду.

**Перенос.** Да — часть расширений может быть выделена и перенесена при пересмотре цели.

### S4-04 · Улучшение устойчивости голосования (L3)

**Ожидаемый результат.** L3: Уточнена обработка повторных, конкурентных и запоздавших действий в уже рабочем сценарии нескольких участников.

**Граница.** Дополнительная устойчивость сверх обязательной работоспособности.

**Перенос.** Да — по отдельным улучшениям, если базовая корректность L2 не нарушена.

## 7. Спринт 5 — «Передача результата»

**Цель.** Экспорт результатов в согласованном CSV-формате, опциональные интеграции, необходимые улучшения интерфейса и передача проверенного продукта.

### S5-01 · Экспорт итогов в CSV (L2)

**Ожидаемый результат.** L2: Пользователь выгружает CSV с реальными итоговыми SP задач. Для импортированного файла сохраняется соответствие колонок, чтобы итоговые значения можно было записать в ранее выбранную колонку назначения SP и использовать файл вне приложения.

**Граница.** Новые итоговые SP заменяют содержимое выбранной пользователем колонки в выгружаемом CSV, остальные исходные колонки должны сохранять свой смысл. Приложение не создаёт отсутствующую целевую колонку самостоятельно. Без обязательной прямой интеграции YouTrack и других форматов.

**Перенос.** Нет — если экспорт является обязательной частью итогового результата.

### S5-02 · Импорт Excel (L2)

**Ожидаемый результат.** L2: Приложение читает предусмотренный формат Excel и создаёт реальные задачи по тем же продуктовым правилам, что CSV.

**Граница.** Excel, без расширенного произвольного сопоставления нестандартных таблиц.

**Перенос.** Да — при согласовании итогового объёма.

### S5-03 · Интеграция с YouTrack (L2)

**Ожидаемый результат.** L2: Реализована выбранная операция обмена задачами или оценками с YouTrack, если подтверждены объём, доступ и требования.

**Граница.** Только отдельно определённый сценарий обмена; полная двусторонняя синхронизация заранее не предполагается.

**Перенос.** Да — условная интеграция может быть перенесена или исключена из итогового объёма.

### S5-04 · Полноценный лендинг и точки входа (L2)

**Ожидаемый результат.** L2: Реализован полноценный лендинг с работающими переходами к созданию и подключению к сессии.

**Граница.** Лендинг относится к финализации, без изменения основного сценария оценки.

**Перенос.** Да — полноценное оформление лендинга не блокирует рабочий продукт.

### S5-05 · Улучшение интерфейса основных сценариев (L3)

**Ожидаемый результат.** L3: Повышены удобство, адаптивность и качество состояний загрузки, ошибок и пустых списков в существующих рабочих функциях.

**Граница.** Не заменяет ранее обязательные базовые состояния и ошибки.

**Перенос.** Да — отдельные улучшения можно перенести, сохранив L2.

### S5-06 · Актуализация документации и итоговая проверка (—)

**Ожидаемый результат.** Актуализированы инструкции запуска, архитектурные материалы, описание API и исследования эталонов; полный продуктовый сценарий проверен на подготовленном окружении.

**Граница.** Обновление ранее ведущейся документации, а не создание всех материалов в конце проекта.

**Перенос.** Нет — обязательная часть передачи результата.

### S5-07 · Вложения и прочие расширения (L2)

**Ожидаемый результат.** L2: Добавлены минимально рабочие дополнительные возможности, если они включены в итоговый согласованный объём.

**Граница.** Объём уточняется по аналитической спецификации.

**Перенос.** Да — без влияния на обязательный приёмочный сценарий.

## 8. Открытые продуктовые границы

Эти вопросы не являются предписаниями для разработчиков и не блокируют обсуждение технической реализации остальных задач. Решение принимает PM/PO по мере приближения соответствующего сценария.

- S1 / S3: нужно ли разрешить минимальное ручное добавление одной задачи уже в первом однопользовательском сценарии, или оставить его полностью для S3-01? В текущем плане — S3-01.
- S1 / S3: завершение сессии после последней оценки происходит автоматически или по отдельному действию Host? В документах встречаются оба варианта.
- S2: в какой момент остальным участникам становятся видны выбранные значения карт? Это поведение требуется согласовать отдельно, до реализации совместного голосования.
- S1: предельный размер CSV и допустимое число задач — согласовать по инженерному предложению и реальным потребностям пользователя (первоначальные 2 МБ / 200 задач предварительны).
Статус: рабочий документ для продуктового согласования. Не заменяет технический бэклог, аналитические рамки отдельных задач и план итеративной разработки.
