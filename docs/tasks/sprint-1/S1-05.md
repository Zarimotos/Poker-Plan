# ТЗ: S1-05 · Фиксация итогового SP и переход к следующей задаче

**Статус:** рабочее ТЗ для разработки  
**Спринт:** 1 — «Скелет продукта»  
**Целевой уровень:** L2 — минимально работающая функция  
**Перенос:** Нет — выбор карты без сохранённого результата недостаточен  
**Ответственный за продуктовые решения:** тимлид (PM/PO)  
**Ответственные за реализацию:** тимлид и разработчики  

## 1. Основная идея

Host подтверждает окончательное числовое SP для текущей задачи. После подтверждения значение сохраняется на сервере и остаётся доступным после перезагрузки страницы. Затем Host может перейти к следующей задаче и повторить оценку.

Выбор карты в S1-04 является предварительным локальным состоянием. Только подтверждённый итоговый SP становится сохранённым результатом задачи.

## 2. Пользовательский сценарий

1. Host находится на экране оценки текущей задачи.
2. Host выбирает числовую карту SP.
3. Host нажимает «Подтвердить».
4. Система сохраняет выбранное значение как итоговый SP текущей задачи на сервере.
5. Система отображает подтверждённый итоговый SP.
6. Host переходит к следующей задаче из очереди.
7. Host повторяет оценку для следующей задачи.
8. Если подтверждена последняя задача, Host переходит к итогам сессии в рамках S1-06.

## 3. Требования к поведению

### 3.1. Подтверждение итогового SP

- Host может подтвердить итоговый SP только после выбора числовой карты SP.
- Подтверждённое значение должно быть сохранено на сервере.
- Подтверждённый итоговый SP должен быть привязан к текущей задаче.
- После подтверждения значение должно отображаться как итоговый SP задачи.
- После подтверждения Host должен иметь возможность перейти к следующей задаче.
- Повторное подтверждение без изменения выбора не должно создавать несколько итоговых значений для одной задачи.

### 3.2. Сохранность результата

- Подтверждённый итоговый SP должен сохраняться на сервере.
- После обновления страницы Host должен видеть сохранённый итоговый SP.
- После повторного открытия сессии по идентификатору сохранённый итоговый SP должен оставаться доступным.
- Сохранённый итоговый SP не должен исчезать при переходе к следующей задаче.

### 3.3. Переход к следующей задаче

- После подтверждения итогового SP Host может перейти к следующей неоценённой задаче.
- Следующей задачей считается следующая задача в порядке очереди.
- Если текущая задача была последней в очереди, Host должен перейти к итогам сессии в рамках S1-06.
- До подтверждения итогового SP переход к следующей задаче через основной сценарий оценки недоступен.

### 3.4. Изменение выбора до подтверждения

- До подтверждения Host может изменить предварительный выбор карты SP.
- После подтверждения итоговый SP считается зафиксированным для текущей задачи.
- Переголосование и изменение уже подтверждённого итогового SP в S1-05 не входят.

## 4. Обязательные данные

Для подтверждения итогового SP необходимы:

- Текущая задача.
- Выбранная числовая карта SP.
- Подтверждение действия Host.

Для сохранённого результата должны быть доступны:

- Идентификатор задачи.
- Подтверждённый итоговый SP.
- Признак, что задача оценена.

## 5. Ограничения и правила

- Подтверждает итоговый SP только Host.
- Participant не входит в S1-05.
- Подтверждается только числовое значение SP.
- Специальные карты не поддерживаются.
- Таймер не реализуется.
- Исторические эталоны не отображаются.
- Комментарии не реализуются.
- Статистика голосов не рассчитывается.
- Переголосование не реализуется.
- Изменение уже подтверждённого итогового SP не входит в S1-05.
- Управление очередью не входит в S1-05.
- Итоги сессии отображаются в S1-06.

## 6. Ошибки и состояния

### 6.1. Отсутствие выбранной карты

- Если Host не выбрал карту SP, кнопка «Подтвердить» должна быть недоступна.
- Система должна показывать подсказку: «Выберите карту SP».

### 6.2. Ошибка подтверждения

- Если сервер не смог сохранить итоговый SP, Host должен увидеть понятное сообщение об ошибке.
- После ошибки Host должен иметь возможность повторить подтверждение.
- Если сохранение не выполнено, задача не должна считаться оценённой.

### 6.3. Ошибка перехода

- Если следующая задача не найдена, Host должен увидеть понятное сообщение об ошибке.
- Если сессия недоступна, отображается сообщение: «Сессия временно недоступна».
- Если текущая задача не найдена, отображается сообщение: «Задача не найдена».

## 7. Критерии приёмки

### AC-1. Подтверждение выбранного SP

**Дано:** Host выбрал числовую карту SP для текущей задачи.  
**Когда:** Host нажимает «Подтвердить».  
**Тогда:** выбранное значение сохраняется на сервере как итоговый SP текущей задачи.

### AC-2. Отображение подтверждённого SP

**Дано:** Host подтвердил итоговый SP.  
**Когда:** Host находится на экране текущей задачи или возвращается к ней.  
**Тогда:** отображается сохранённый итоговый SP.

### AC-3. Сохранность после обновления

**Дано:** Host подтвердил итоговый SP.  
**Когда:** Host обновляет страницу или повторно открывает сессию.  
**Тогда:** подтверждённый итоговый SP остаётся доступным.

### AC-4. Переход к следующей задаче

**Дано:** Host подтвердил итоговый SP текущей задачи.  
**Когда:** Host переходит к следующей задаче.  
**Тогда:** открывается следующая неоценённая задача из очереди.

### AC-5. Переход к итогам после последней задачи

**Дано:** Host подтвердил итоговый SP последней задачи в очереди.  
**Когда:** система обрабатывает подтверждение.  
**Тогда:** Host переходит к итогам сессии в рамках S1-06.

### AC-6. Блокировка подтверждения без выбора

**Дано:** Host не выбрал карту SP.  
**Когда:** Host пытается подтвердить итоговый SP.  
**Тогда:** подтверждение недоступно, а система показывает подсказку о необходимости выбрать карту.

### AC-7. Ошибка сохранения

**Дано:** Сервер недоступен или произошла ошибка при сохранении итогового SP.  
**Когда:** Host нажимает «Подтвердить».  
**Тогда:** отображается понятное сообщение об ошибке, а задача не считается оценённой.

## 8. Предлагаемый вариант интерфейса

Этот раздел — предложение для согласования, а не обязательное техническое решение.

### 8.1. Экран оценки задачи

- Заголовок: «Оценка задачи».
- Прогресс: «Задача N из M».
- Блок с ID задачи.
- Заголовок задачи.
- Панель числовых карт SP.
- Выбранная карта SP.
- Кнопка «Подтвердить» — доступна только после выбора карты.
- После подтверждения — отображение итогового SP.
- Кнопка «Следующая задача» — доступна после подтверждения.
- Кнопка «Назад в лобби».

### 8.2. Состояния экрана

- Загрузка: «Загружаем задачу…».
- Без выбора: «Выберите карту SP».
- Выбрана карта: отображается выбранное значение SP.
- Сохранение: «Сохраняем итоговый SP…».
- Подтверждено: «Итоговый SP: [значение]».
- Ошибка сохранения: «Не удалось сохранить итоговый SP. Попробуйте ещё раз».

## 9. Предлагаемый технический вариант

Этот раздел не является обязательным техническим решением. Разработчики вправе выбрать собственную реализацию, если она удовлетворяет требованиям и критериям приёмки.

- Подтверждение может быть реализовано через серверное действие, которое принимает идентификатор задачи и выбранное числовое значение SP.
- Сервер может сохранять итоговый SP как отдельный результат задачи и отмечать задачу как оценённую.
- Для определения следующей задачи может использоваться порядок очереди и признак наличия сохранённого итогового SP.
- После подтверждения последней задачи клиент может перейти на экран итогов сессии.
- Предварительный выбор карты может храниться в локальном состоянии клиента до подтверждения.

## 10. Решённые продуктовые решения

- Host подтверждает окончательное числовое SP для текущей задачи.
- Итоговый SP сохраняется на сервере.
- Подтверждённый итоговый SP доступен после перезагрузки страницы.
- После подтверждения Host может перейти к следующей задаче.
- Если подтверждена последняя задача, Host переходит к итогам сессии.
- Выбор карты до подтверждения является локальным предварительным состоянием.
- В S1-05 участвует только Host.
- Переголосование и изменение уже подтверждённого итогового SP не входят в S1-05.

## 11. Открытые вопросы

Открытых продуктовых вопросов, влияющих на реализацию S1-05 и не согласованных ранее, нет.

## 12. Что не входит в S1-05

- Подключение Participant по коду или ссылке.
- Голоса Participant.
- Таймер и продление раунда.
- Специальные карты.
- Исторические эталоны.
- Комментарии.
- Расчёт и отображение статистики.
- Переголосование.
- Изменение уже подтверждённого итогового SP.
- Управление очередью.
- Экран итогов сессии.
- Экспорт CSV, Excel и интеграция с YouTrack.
- Управление ролями, завершение сессии и удаление сессии.
