# ТЗ: S1-03 · Просмотр очереди импортированных задач

**Статус:** рабочее ТЗ для разработки  
**Спринт:** 1 — «Скелет продукта»  
**Целевой уровень:** L2 — минимально работающая функция  
**Перенос:** Нет — нужен переход от импорта к оценке  
**Ответственный за продуктовые решения:** тимлид (PM/PO)  
**Ответственные за реализацию:** тимлид и разработчики  

## 1. Основная идея

Host видит в лобби актуальный список задач, которые были действительно импортированы в серверную очередь сессии. Список формируется на основе серверных данных и отражает порядок импорта задач.

Очередь предназначена только для просмотра и перехода к оценке. Host не может добавлять, удалять, переставлять или пропускать задачи. Эти возможности появятся в S3-01.

## 2. Пользовательский сценарий

1. Host создаёт сессию и попадает в лобби.
2. Host импортирует задачи из CSV.
3. После успешного импорта Host видит обновлённый список задач в очереди.
4. Host видит количество задач в очереди.
5. Host может просмотреть основные сведения каждой задачи.
6. Host может перейти к оценке первой задачи из очереди.
7. После обновления страницы список задач остаётся доступным.

## 3. Требования к поведению

### 3.1. Отображение очереди

- В лобби Host должен видеть список задач, реально импортированных в сессию.
- Список должен формироваться на основе серверных данных очереди.
- Порядок задач должен соответствовать порядку, в котором они были импортированы.
- Если в очереди нет задач, должно отображаться пустое состояние.
- Если задачи были успешно импортированы, пустое состояние не должно отображаться.
- Список должен обновляться после успешного импорта.

### 3.2. Содержание карточки задачи

Для каждой задачи в очереди Host должен видеть как минимум:

- Порядковый номер задачи в очереди.
- ID задачи.
- Заголовок задачи.

Допустимо отображать дополнительные данные, если они были импортированы:

- Описание задачи.
- Ссылка YouTrack.
- Дополнительные характеристики задачи.

Отображение дополнительных данных не является обязательным для S1-03, если это не мешает основному сценарию.

### 3.3. Количество задач

- Host должен видеть количество задач в очереди.
- Количество должно соответствовать числу задач, фактически сохранённых на сервере.
- После успешного импорта количество должно увеличиться на число добавленных корректных задач.
- Если очередь пуста, должно отображаться значение 0 либо понятное пустое состояние.

### 3.4. Переход к оценке

- Host должен иметь возможность перейти к оценке первой задачи из очереди.
- Переход должен быть доступен только при наличии хотя бы одной задачи в очереди.
- Если очередь пуста, переход к оценке должен быть недоступен или скрыт.
- После перехода Host должен видеть сведения первой задачи из серверной очереди.

### 3.5. Сохранность очереди

- После обновления страницы очередь должна оставаться доступной.
- После повторного открытия сессии по идентификатору список задач должен отображаться в актуальном состоянии.
- Импортированные задачи не должны исчезать после перезагрузки страницы.
- Если сервер недоступен, Host должен получить понятное сообщение об ошибке.

## 4. Обязательные данные

Для каждой задачи в очереди должны отображаться как минимум:

- Порядковый номер.
- ID задачи.
- Заголовок задачи.

Для очереди в целом должны быть доступны:

- Общее количество задач.
- Пустое состояние при отсутствии задач.
- Возможность перехода к оценке при наличии задач.

## 5. Ограничения и правила

- Очередь предназначена только для просмотра.
- Host не может добавлять задачи вручную.
- Host не может удалять задачи из очереди.
- Host не может менять порядок задач.
- Host не может пропускать задачи.
- Host не может редактировать сведения задачи из очереди.
- Participant не входит в S1-03.
- Не требуется отображение статуса оценки задачи.
- Не требуется отображение итогового SP.
- Не требуется отображение статистики, комментариев, эталонов и таймера.
- Не требуется реализация поиска, фильтрации или сортировки задач.
- Не требуется пагинация, если она не нужна для корректной работы с согласованным объёмом задач.

## 6. Ошибки и состояния

### 6.1. Пустая очередь

- Если задачи не импортированы, отображается сообщение: «Задачи ещё не добавлены».
- Вместе с пустым состоянием может отображаться подсказка о необходимости импортировать CSV.
- Переход к оценке при пустой очереди недоступен.

### 6.2. Ошибка загрузки очереди

- Если список задач не удалось загрузить, отображается понятное сообщение об ошибке.
- Host должен иметь возможность повторить загрузку очереди.
- При ошибке не должны отображаться устаревшие или вымышленные задачи.

### 6.3. Ошибка перехода к оценке

- Если переход к оценке невозможен, Host должен увидеть понятное сообщение об ошибке.
- Если задача не найдена, отображается сообщение: «Задача не найдена».
- Если сессия недоступна, отображается сообщение: «Сессия временно недоступна».

## 7. Критерии приёмки

### AC-1. Отображение импортированных задач

**Дано:** Host успешно импортировал корректные задачи из CSV.  
**Когда:** Host находится в лобби.  
**Тогда:** отображаются все импортированные задачи с порядковым номером, ID и заголовком.

### AC-2. Соответствие количеству задач

**Дано:** В очередь успешно импортировано N корректных задач.  
**Когда:** Host находится в лобби.  
**Тогда:** отображается количество N задач.

### AC-3. Порядок после импорта

**Дано:** Host импортировал несколько задач.  
**Когда:** Host просматривает очередь.  
**Тогда:** задачи отображаются в порядке их импорта.

### AC-4. Пустая очередь

**Дано:** В сессии нет импортированных задач.  
**Когда:** Host находится в лобби.  
**Тогда:** отображается пустое состояние, а переход к оценке недоступен.

### AC-5. Переход к оценке

**Дано:** В очереди есть хотя бы одна задача.  
**Когда:** Host нажимает переход к оценке.  
**Тогда:** Host попадает на экран оценки первой задачи из очереди.

### AC-6. Сохранность после обновления

**Дано:** Host ранее импортировал задачи.  
**Когда:** Host обновляет страницу или повторно открывает сессию.  
**Тогда:** очередь отображается в актуальном состоянии с ранее импортированными задачами.

### AC-7. Ошибка загрузки очереди

**Дано:** Сервер недоступен или произошла ошибка при получении очереди.  
**Когда:** Host находится в лобби.  
**Тогда:** отображается понятное сообщение об ошибке, а Host может повторить загрузку.

## 8. Предлагаемый вариант интерфейса

Этот раздел — предложение для согласования, а не обязательное техническое решение.

### 8.1. Блок очереди в лобби

- Заголовок: «Очередь задач».
- Счётчик: «Задач в очереди: N».
- Список задач.
- Для каждой задачи:
  - порядковый номер;
  - ID задачи;
  - заголовок задачи.
- Кнопка «Начать оценку» либо аналогичный переход к первой задаче.
- Пустое состояние: «Задачи ещё не добавлены».

### 8.2. Состояния списка

- Загрузка: «Загружаем очередь задач…».
- Пустая очередь: «Задачи ещё не добавлены».
- Ошибка: «Не удалось загрузить очередь задач. Попробуйте ещё раз».
- Ошибка перехода: «Не удалось открыть задачу для оценки».

## 9. Предлагаемый технический вариант

Этот раздел не является обязательным техническим решением. Разработчики вправе выбрать собственную реализацию, если она удовлетворяет требованиям и критериям приёмки.

- Очередь может быть получена из сервера по идентификатору сессии, созданному в S1-01.
- Порядок задач может определяться порядком их добавления при импорте.
- Список может загружаться при открытии лобби и обновляться после успешного импорта.
- Для перехода к оценке может использоваться идентификатор первой задачи либо её позиция в очереди.
- Пустое состояние, состояние загрузки и ошибка должны быть различимы для пользователя.

## 10. Решённые продуктовые решения

- Очередь отображает только задачи, реально импортированные в серверную сессию.
- Порядок задач соответствует порядку импорта.
- Для каждой задачи обязательно отображаются порядковый номер, ID и заголовок.
- Host видит количество задач в очереди.
- Host может перейти к оценке первой задачи.
- При пустой очереди переход к оценке недоступен.
- Очередь сохраняется на сервере и доступна после обновления страницы.
- В S1-03 управление очередью не реализуется.

## 11. Открытые вопросы

Открытых продуктовых вопросов, влияющих на реализацию S1-03 и не согласованных ранее, нет.

## 12. Что не входит в S1-03

- Подключение Participant по коду или ссылке.
- Добавление, удаление, перестановка и пропуск задач.
- Редактирование сведений задачи.
- Просмотр и оценка текущей задачи.
- Выбор и подтверждение итогового SP.
- Экран итогов сессии.
- Экспорт CSV, Excel и интеграция с YouTrack.
- Таймер, комментарии, исторические эталоны и расширенная статистика.
- Управление ролями, завершение сессии и удаление сессии.
