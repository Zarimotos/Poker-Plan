# ТЗ: S1-07 · Восстановление состояния и обработка базовых ошибок

**Статус:** рабочее ТЗ для разработки  
**Спринт:** 1 — «Скелет продукта»  
**Целевой уровень:** L2 — минимально работающая функция  
**Перенос:** Нет — в части сохранности и работоспособности основного сценария  
**Ответственный за продуктовые решения:** тимлид (PM/PO)  
**Ответственные за реализацию:** тимлид и разработчики  

## 1. Основная идея

Перезагрузка страницы не должна уничтожать серверную сессию, импортированную очередь и подтверждённые итоговые SP. Основные операции однопользовательского сценария при ошибке должны давать Host понятную обратную связь и возможность повторить действие.

Задача охватывает базовую устойчивость уже реализованного пути: создание сессии, импорт CSV, просмотр очереди, выбор SP, подтверждение итогового SP и просмотр итогов. Детальная UX-полировка и обработка редких исключений выполняются позднее.

## 2. Пользовательский сценарий

1. Host создаёт сессию.
2. Host импортирует задачи из CSV.
3. Host оценивает одну или несколько задач и подтверждает итоговые SP.
4. Host обновляет страницу.
5. Система восстанавливает актуальное состояние сессии из серверных данных.
6. Host видит сохранённую очередь и подтверждённые итоговые SP.
7. Если операция завершилась ошибкой, Host видит понятное сообщение и может повторить действие.

## 3. Требования к поведению

### 3.1. Восстановление сессии

- После обновления страницы сессия должна оставаться доступной по её идентификатору.
- После повторного открытия сессии Host должен видеть актуальные серверные данные.
- Импортированные задачи должны оставаться в очереди.
- Подтверждённые итоговые SP должны сохраняться.
- Состояние сессии должно определяться сервером, а не только локальным состоянием браузера.

### 3.2. Восстановление очереди

- После обновления страницы Host должен видеть список задач, реально импортированных в сессию.
- Порядок задач должен соответствовать порядку импорта.
- Если задачи не были импортированы, должно отображаться пустое состояние очереди.
- Если список задач не удалось загрузить, Host должен увидеть понятное сообщение об ошибке.

### 3.3. Восстановление результатов

- После обновления страницы Host должен видеть подтверждённые итоговые SP.
- Для неоценённых задач итоговый SP не отображается.
- Подтверждённый итоговый SP должен быть привязан к соответствующей задаче.
- Если результаты не удалось загрузить, Host должен увидеть понятное сообщение об ошибке.

### 3.4. Обработка базовых ошибок

- При ошибке создания сессии Host должен увидеть понятное сообщение.
- При ошибке импорта CSV Host должен увидеть понятное сообщение.
- При ошибке загрузки очереди Host должен увидеть понятное сообщение.
- При ошибке загрузки текущей задачи Host должен увидеть понятное сообщение.
- При ошибке подтверждения итогового SP Host должен увидеть понятное сообщение.
- При ошибке загрузки итогов Host должен увидеть понятное сообщение.
- После ошибки Host должен иметь возможность повторить соответствующее действие.

## 4. Обязательные данные

Для восстановления состояния должны быть доступны:

- Идентификатор сессии.
- Название сессии.
- Имя Host.
- Роль Host.
- Список импортированных задач.
- Подтверждённые итоговые SP.

Для обработки ошибок должны быть доступны:

- Понятное сообщение об ошибке.
- Возможность повторить действие.
- Сохранение уже успешно выполненных действий.

## 5. Ограничения и правила

- Восстановление состояния относится к однопользовательскому сценарию Host.
- Participant не входит в S1-07.
- Восстанавливаются только данные, которые уже сохранены на сервере.
- Локальный предварительный выбор карты SP до подтверждения не обязан сохраняться после обновления страницы.
- Детальная UX-полировка не входит в S1-07.
- Редкие исключения и сложные сценарии восстановления не входят в S1-07.
- Не требуется реализация офлайн-режима.
- Не требуется автоматическое повторное выполнение неудачных операций.
- Не требуется восстановление состояния после закрытия браузера, если сессия уже доступна по идентификатору.

## 6. Ошибки и состояния

### 6.1. Ошибка создания сессии

- Если сервер не смог создать сессию, Host должен увидеть понятное сообщение об ошибке.
- После ошибки Host должен иметь возможность повторить создание сессии.

### 6.2. Ошибка импорта CSV

- Если CSV не удалось прочитать, проверить или сохранить, Host должен увидеть понятное сообщение об ошибке.
- После ошибки Host должен иметь возможность повторить импорт.
- Очередь не должна содержать частично добавленные задачи без явного указания на это.

### 6.3. Ошибка загрузки очереди

- Если список задач не удалось загрузить, отображается сообщение: «Не удалось загрузить очередь задач. Попробуйте ещё раз».
- Host должен иметь возможность повторить загрузку.

### 6.4. Ошибка загрузки задачи

- Если текущую задачу не удалось загрузить, отображается сообщение: «Не удалось загрузить задачу. Попробуйте ещё раз».
- Host должен иметь возможность повторить загрузку.

### 6.5. Ошибка подтверждения SP

- Если итоговый SP не удалось сохранить, отображается сообщение: «Не удалось сохранить итоговый SP. Попробуйте ещё раз».
- После ошибки Host должен иметь возможность повторить подтверждение.
- Задача не должна считаться оценённой, если итоговый SP не сохранён.

### 6.6. Ошибка загрузки итогов

- Если итоги не удалось загрузить, отображается сообщение: «Не удалось загрузить итоги сессии. Попробуйте ещё раз».
- Host должен иметь возможность повторить загрузку.

## 7. Критерии приёмки

### AC-1. Восстановление сессии после обновления

**Дано:** Host создал сессию.  
**Когда:** Host обновляет страницу или повторно открывает сессию по идентификатору.  
**Тогда:** сессия остаётся доступной, а её основные данные сохраняются.

### AC-2. Восстановление очереди после обновления

**Дано:** Host успешно импортировал задачи.  
**Когда:** Host обновляет страницу.  
**Тогда:** очередь отображается в актуальном состоянии с ранее импортированными задачами.

### AC-3. Восстановление итоговых SP после обновления

**Дано:** Host подтвердил итоговые SP для одной или нескольких задач.  
**Когда:** Host обновляет страницу.  
**Тогда:** подтверждённые итоговые SP остаются доступными.

### AC-4. Неоценённые задачи после обновления

**Дано:** В очереди есть задачи без подтверждённого итогового SP.  
**Когда:** Host обновляет страницу.  
**Тогда:** такие задачи остаются в очереди, а итоговый SP для них не отображается.

### AC-5. Повтор импорта после ошибки

**Дано:** Импорт CSV завершился ошибкой.  
**Когда:** Host повторяет импорт.  
**Тогда:** Host может загрузить CSV и повторить операцию.

### AC-6. Повтор подтверждения после ошибки

**Дано:** Подтверждение итогового SP завершилось ошибкой.  
**Когда:** Host повторяет подтверждение.  
**Тогда:** Host может выбрать карту и повторно подтвердить итоговый SP.

### AC-7. Понятная ошибка при недоступности сервера

**Дано:** Сервер недоступен.  
**Когда:** Host выполняет основную операцию.  
**Тогда:** отображается понятное сообщение об ошибке, а Host может повторить действие.

## 8. Предлагаемый вариант интерфейса

Этот раздел — предложение для согласования, а не обязательное техническое решение.

### 8.1. Состояния интерфейса

- Загрузка: «Загружаем данные сессии…».
- Пустая очередь: «Задачи ещё не добавлены».
- Ошибка загрузки: «Не удалось загрузить данные. Попробуйте ещё раз».
- Ошибка сохранения: «Не удалось сохранить результат. Попробуйте ещё раз».
- Ошибка импорта: «Не удалось импортировать задачи. Попробуйте ещё раз».

### 8.2. Действия при ошибке

- Кнопка «Повторить» для повторной загрузки или сохранения.
- Возможность вернуться в лобби.
- Возможность повторить импорт CSV.
- Возможность повторно подтвердить итоговый SP.

## 9. Предлагаемый технический вариант

Этот раздел не является обязательным техническим решением. Разработчики вправе выбрать собственную реализацию, если она удовлетворяет требованиям и критериям приёмки.

- Состояние сессии может восстанавливаться по идентификатору сессии из S1-01.
- Очередь и подтверждённые итоговые SP могут быть получены из серверных данных.
- Предварительный выбор карты SP может храниться в локальном состоянии клиента и не обязан сохраняться после обновления.
- Для ошибок могут использоваться понятные сообщения и возможность повторить действие.
- Для повторного открытия сессии может использоваться прямая ссылка вида `/room/{session_id}` либо иной согласованный маршрут.

## 10. Решённые продуктовые решения

- Перезагрузка страницы не уничтожает серверную сессию.
- Импортированная очередь сохраняется на сервере.
- Подтверждённые итоговые SP сохраняются на сервере.
- После обновления страницы Host видит актуальные данные сессии.
- Основные операции при ошибке дают понятную обратную связь.
- После ошибки Host может повторить действие.
- Восстановление состояния относится к однопользовательскому сценарию Host.
- Детальная UX-полировка и редкие исключения не входят в S1-07.

## 11. Открытые вопросы

Открытых продуктовых вопросов, влияющих на реализацию S1-07 и не согласованных ранее, нет.

## 12. Что не входит в S1-07

- Подключение Participant по коду или ссылке.
- Восстановление состояния нескольких участников.
- Таймер и продление раунда.
- Специальные карты.
- Исторические эталоны.
- Комментарии.
- Расчёт и отображение многопользовательской статистики.
- Переголосование.
- Управление очередью.
- Экспорт CSV, Excel и интеграция с YouTrack.
- Детальная UX-полировка и обработка редких исключений.
- Управление ролями, завершение сессии и удаление сессии.
