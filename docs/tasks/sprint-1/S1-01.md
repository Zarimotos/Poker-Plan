# ТЗ: S1-01 · Создание сессии и переход ведущего в лобби

**Статус:** рабочее ТЗ для разработки  
**Спринт:** 1 — «Скелет продукта»  
**Целевой уровень:** L2 — минимально работающая функция  
**Перенос:** Нет — входная точка обязательного пользовательского пути  
**Ответственный за продуктовые решения:** тимлид (PM/PO)  
**Ответственные за реализацию:** тимлид и разработчики  

## 1. Основная идея

Host создаёт новую сессию через интерфейс, получает идентификатор, сформированный сервером, и попадает в лобби этой сессии. Сессия сохраняется на сервере, поэтому Host может вернуться к ней повторно по идентификатору после обновления страницы или повторного перехода по ссылке.

На уровне S1-01 реализуются только создание сессии и просмотр лобби Host. Подключение участников, импорт задач, управление очередью, оценка и фиксация SP не входят.

## 2. Пользовательский сценарий

1. Host открывает точку входа для создания сессии.
2. Host вводит название сессии и своё имя.
3. Host нажимает «Создать сессию».
4. Система создаёт сессию на сервере и формирует её идентификатор.
5. Host автоматически попадает в лобби созданной сессии.
6. В лобби Host видит основные данные созданной сессии.
7. Host может вернуться к этой же сессии позже по её идентификатору или ссылке.

## 3. Требования к поведению

### 3.1. Создание сессии

- Host может создать сессию только после успешной отправки формы создания.
- Сервер создаёт сессию и формирует её уникальный идентификатор.
- Идентификатор сессии должен быть пригоден для повторного обращения к сессии.
- После успешного создания Host должен быть переведён в лобби созданной сессии.
- Host должен быть распознан как ведущий созданной сессии.
- Созданная сессия должна сохраняться на сервере.
- Обновление страницы не должно приводить к исчезновению созданной сессии.

### 3.2. Лобби Host

После перехода в лобби Host должен видеть как минимум:

- Название сессии.
- Имя Host.
- Идентификатор сессии либо возможность его скопировать.
- Признак роли Host.
- Пустое или нулевое состояние очереди задач.
- Указание, что участники ещё не подключены либо что подключение участников появится позднее.

Лобби должно быть доступно повторно по идентификатору сессии. При повторном открытии система должна показывать актуальные данные этой сессии.

### 3.3. Повторный доступ к сессии

- По известному идентификатору сессии Host должен иметь возможность открыть её лобби повторно.
- При повторном открытии должны отображаться сохранённые на сервере данные сессии.
- Если сессия по идентификатору не найдена, пользователь должен получить понятное сообщение об ошибке.
- Если идентификатор некорректен, пользователь должен получить понятное сообщение об ошибке.

## 4. Обязательные данные

Для создания сессии обязательны:

- Название сессии.
- Имя Host.

Для созданной сессии сервер должен сохранять как минимум:

- Идентификатор сессии.
- Название сессии.
- Имя Host.
- Роль Host.
- Текущее состояние сессии.

## 5. Ограничения и правила

- Создаёт сессию только Host.
- В рамках S1-01 не требуется возможность подключать Participant.
- Не требуется реализация импорта задач, добавления задач вручную, управления очередью, оценки и фиксации SP.
- Не требуется реализация таймера, комментариев, исторических эталонов, статистики и экспорта.
- Не требуется возможность передавать роль Host другому пользователю.
- Не требуется реализация удаления, архивирования или завершения сессии.
- Допустимо, если в лобби отображаются визуальные области для будущих функций; такие области должны быть скрыты либо явно неактивны.

## 6. Ошибки и состояния

### 6.1. Ошибки формы

- Если обязательные поля не заполнены, система должна показать понятное сообщение и не создавать сессию.
- Если введённые данные не проходят базовую валидацию, система должна показать понятное сообщение и не создавать сессию.
- Ошибки должны быть привязаны к соответствующему полю либо отображаться рядом с формой.

### 6.2. Ошибки создания

- Если сервер не смог создать сессию, Host должен увидеть понятное сообщение об ошибке.
- После ошибки Host должен иметь возможность повторить попытку создания сессии.
- Повторная попытка не должна приводить к появлению нескольких сессий без явного действия Host.

### 6.3. Ошибки открытия сессии

- Если сессия не найдена, отображается сообщение: «Сессия не найдена».
- Если идентификатор некорректен, отображается сообщение: «Некорректный идентификатор сессии».
- Если сессия временно недоступна, отображается понятное сообщение об ошибке и возможность повторить попытку.

## 7. Критерии приёмки

### AC-1. Успешное создание сессии

**Дано:** Host находится на экране создания сессии.  
**Когда:** Host вводит валидные название сессии и имя, затем нажимает «Создать сессию».  
**Тогда:** система создаёт сессию на сервере, формирует идентификатор и переводит Host в лобби этой сессии.

### AC-2. Отображение данных в лобби

**Дано:** Host успешно создал сессию.  
**Когда:** Host находится в лобби.  
**Тогда:** отображаются название сессии, имя Host, идентификатор сессии и признак роли Host.

### AC-3. Повторное открытие сессии

**Дано:** Host ранее создал сессию и знает её идентификатор.  
**Когда:** Host открывает сессию повторно по идентификатору или ссылке.  
**Тогда:** система показывает лобби этой же сессии с сохранёнными данными.

### AC-4. Сохранность после обновления

**Дано:** Host находится в лобби созданной сессии.  
**Когда:** Host обновляет страницу.  
**Тогда:** сессия остаётся доступной, а её основные данные сохраняются.

### AC-5. Ошибка при незаполненных полях

**Дано:** Host находится на экране создания сессии.  
**Когда:** Host отправляет форму с незаполненным обязательным полем.  
**Тогда:** сессия не создаётся, а система показывает понятное сообщение об ошибке.

### AC-6. Ошибка при несуществующей сессии

**Дано:** Host пытается открыть сессию по несуществующему идентификатору.  
**Когда:** система обрабатывает запрос.  
**Тогда:** отображается сообщение «Сессия не найдена», а Host не попадает в лобби.

## 8. Предлагаемый вариант интерфейса

Этот раздел — предложение для согласования, а не обязательное техническое решение.

### 8.1. Экран создания сессии

- Заголовок: «Создание сессии».
- Поле «Название сессии» — обязательное.
- Поле «Имя ведущего» — обязательное.
- Кнопка «Создать сессию» — основное действие.
- Кнопка «Назад» — возврат на предыдущий экран.

### 8.2. Экран лобби Host

- Заголовок с названием сессии.
- Блок с именем Host и ролью «Ведущий».
- Блок с идентификатором сессии и кнопкой копирования.
- Блок очереди задач с пустым состоянием: «Задачи ещё не добавлены».
- Блок участников с пустым состоянием: «Участники ещё не подключены».
- Неактивные или скрытые элементы для будущих функций: импорт задач, добавление задач, управление очередью, участники, комментарии, таймер и эталоны.

## 9. Предлагаемый технический вариант

Этот раздел не является обязательным техническим решением. Разработчики вправе выбрать собственную реализацию, если она удовлетворяет требованиям и критериям приёмки.

- Создание сессии может быть реализовано через серверный endpoint, который принимает название сессии и имя Host, создаёт запись сессии и возвращает её идентификатор.
- Идентификатор может быть короткой человекочитаемой строкой либо UUID; выбор формата остаётся инженерным решением.
- Лобби может получать данные сессии по идентификатору через серверный запрос.
- Состояние сессии может храниться на сервере; клиенту не обязательно хранить все данные локально.
- Для повторного доступа может использоваться прямая ссылка вида `/room/{session_id}` либо иной согласованный маршрут.

## 10. Решённые продуктовые решения

- Название сессии и имя Host обязательны для создания сессии.
- Идентификатор сессии формирует сервер.
- После создания Host попадает в лобби сессии.
- Сессия сохраняется на сервере и доступна повторно по идентификатору.
- В S1-01 подключение участников не реализуется.
- В лобби допускаются неактивные или скрытые области для будущих функций.
- Переименование сессии, отображение даты создания и передача роли Host не входят в S1-01.

## 11. Открытые вопросы

Открытых продуктовых вопросов, влияющих на реализацию S1-01 и не согласованных ранее, нет.

## 12. Что не входит в S1-01

- Подключение Participant по коду или ссылке.
- Импорт CSV и предпросмотр задач.
- Добавление, удаление, перестановка и пропуск задач.
- Просмотр и оценка текущей задачи.
- Выбор и подтверждение итогового SP.
- Экран итогов сессии.
- Экспорт CSV, Excel и интеграция с YouTrack.
- Таймер, комментарии, исторические эталоны и расширенная статистика.
- Управление ролями, завершение сессии и удаление сессии.
