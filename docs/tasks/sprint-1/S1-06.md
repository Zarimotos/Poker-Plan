# ТЗ: S1-06 · Получение итогов сессии

**Статус:** рабочее ТЗ для разработки  
**Спринт:** 1 — «Скелет продукта»  
**Целевой уровень:** L2 — минимально работающая функция  
**Перенос:** Нет — итоги завершают однопользовательский сценарий  
**Ответственный за продуктовые решения:** тимлид (PM/PO)  
**Ответственные за реализацию:** тимлид и разработчики  

## 1. Основная идея

После оценки всех задач Host видит на экране результаты по задачам с реально сохранёнными итоговыми SP. Итоги формируются на основе серверных данных сессии и остаются доступными после обновления страницы.

Показатели, которые не применимы к одиночной оценке, отображаются прочерками. Экспорт CSV, расширенная многопользовательская статистика и YouTrack в S1-06 не входят.

## 2. Пользовательский сценарий

1. Host последовательно оценивает задачи из очереди.
2. Host подтверждает итоговый SP для каждой задачи.
3. После подтверждения последней задачи Host переходит к экрану итогов сессии.
4. Система отображает список всех задач сессии.
5. Для каждой задачи отображается сохранённый итоговый SP.
6. Host видит количество оценённых задач.
7. Host может вернуться в лобби сессии.
8. После обновления страницы итоги остаются доступными.

## 3. Требования к поведению

### 3.1. Переход к итогам

- Host переходит к итогам сессии после подтверждения итогового SP последней задачи.
- Если в очереди есть неоценённые задачи, экран итогов не является завершением основного сценария.
- Host должен иметь возможность вернуться к оценке оставшихся задач.
- Если все задачи оценены, Host должен видеть итоги сессии.

### 3.2. Отображение результатов

- На экране итогов должны отображаться все задачи сессии.
- Для каждой задачи должны отображаться как минимум:
  - порядковый номер;
  - ID задачи;
  - заголовок задачи;
  - сохранённый итоговый SP.
- Итоговый SP должен быть получен из серверных данных, а не из локального состояния клиента.
- Если задача ещё не оценена, вместо итогового SP должно отображаться пустое значение или прочерк.
- Если задача оценена, должен отображаться сохранённый итоговый SP.

### 3.3. Неприменимые показатели

- Показатели, которые не применимы к одиночной оценке, отображаются прочерками.
- К таким показателям относятся, например, среднее, медиана, минимальное и максимальное значения по нескольким голосам.
- Прочерк должен явно показывать, что показатель не рассчитывается в текущем однопользовательском сценарии.
- Не допускается отображение вымышленных или рассчитанных по неполным данным значений.

### 3.4. Сохранность итогов

- Итоги должны формироваться на основе сохранённых на сервере итоговых SP.
- После обновления страницы итоги должны оставаться доступными.
- После повторного открытия сессии по идентификатору итоги должны отображаться в актуальном состоянии.
- Если сервер недоступен, Host должен получить понятное сообщение об ошибке.

## 4. Обязательные данные

Для каждой задачи в итогах должны отображаться как минимум:

- Порядковый номер.
- ID задачи.
- Заголовок задачи.
- Сохранённый итоговый SP либо прочерк, если задача не оценена.

Для экрана итогов должны быть доступны:

- Список всех задач сессии.
- Количество оценённых задач.
- Количество задач в очереди.
- Возможность вернуться в лобби.

## 5. Ограничения и правила

- Итоги доступны Host.
- Participant не входит в S1-06.
- Отображаются только реально сохранённые итоговые SP.
- Неприменимые к одиночной оценке показатели отображаются прочерками.
- Не требуется экспорт CSV.
- Не требуется интеграция с YouTrack.
- Не требуется расширенная многопользовательская статистика.
- Не требуется отображение истории голосов.
- Не требуется отображение комментариев.
- Не требуется отображение исторических эталонов.
- Не требуется управление очередью.
- Не требуется завершение или удаление сессии.

## 6. Ошибки и состояния

### 6.1. Ошибка загрузки итогов

- Если итоги не удалось загрузить, отображается понятное сообщение об ошибке.
- Host должен иметь возможность повторить загрузку итогов.
- При ошибке не должны отображаться вымышленные или устаревшие данные.

### 6.2. Неоценённые задачи

- Если в очереди есть неоценённые задачи, они отображаются с прочерком вместо итогового SP.
- Host должен иметь возможность вернуться к оценке оставшихся задач.
- Наличие неоценённых задач не должно блокировать просмотр уже сохранённых результатов.

### 6.3. Ошибка перехода

- Если переход к итогам невозможен, Host должен увидеть понятное сообщение об ошибке.
- Если сессия не найдена, отображается сообщение: «Сессия не найдена».
- Если сессия недоступна, отображается сообщение: «Сессия временно недоступна».

## 7. Критерии приёмки

### AC-1. Переход к итогам после последней задачи

**Дано:** Host подтвердил итоговый SP последней задачи в очереди.  
**Когда:** система обрабатывает подтверждение.  
**Тогда:** Host попадает на экран итогов сессии.

### AC-2. Отображение сохранённых итогов

**Дано:** Host подтвердил итоговые SP для одной или нескольких задач.  
**Когда:** Host находится на экране итогов.  
**Тогда:** для каждой оценённой задачи отображается сохранённый итоговый SP.

### AC-3. Отображение неоценённых задач

**Дано:** В очереди есть задачи без подтверждённого итогового SP.  
**Когда:** Host находится на экране итогов.  
**Тогда:** для таких задач отображается прочерк вместо итогового SP.

### AC-4. Неприменимые показатели

**Дано:** Host находится на экране итогов в однопользовательском сценарии.  
**Когда:** система формирует результаты.  
**Тогда:** показатели, неприменимые к одиночной оценке, отображаются прочерками.

### AC-5. Сохранность после обновления

**Дано:** Host ранее подтвердил итоговые SP.  
**Когда:** Host обновляет страницу или повторно открывает сессию.  
**Тогда:** итоги отображаются в актуальном состоянии с сохранёнными значениями.

### AC-6. Возврат к оценке

**Дано:** В очереди есть неоценённые задачи.  
**Когда:** Host возвращается к оценке.  
**Тогда:** Host может продолжить оценку оставшихся задач.

### AC-7. Ошибка загрузки итогов

**Дано:** Сервер недоступен или произошла ошибка при получении итогов.  
**Когда:** Host открывает экран итогов.  
**Тогда:** отображается понятное сообщение об ошибке, а Host может повторить загрузку.

## 8. Предлагаемый вариант интерфейса

Этот раздел — предложение для согласования, а не обязательное техническое решение.

### 8.1. Экран итогов сессии

- Заголовок: «Итоги сессии».
- Название сессии.
- Счётчик: «Оценено задач: N из M».
- Таблица результатов:
  - порядковый номер;
  - ID задачи;
  - заголовок задачи;
  - итоговый SP;
  - неприменимые показатели — прочерк.
- Кнопка «Вернуться к оценке» — если есть неоценённые задачи.
- Кнопка «В лобби».
- Пустое состояние, если в сессии нет задач.

### 8.2. Состояния экрана

- Загрузка: «Загружаем итоги сессии…».
- Нет задач: «В сессии пока нет задач».
- Есть неоценённые задачи: «Некоторые задачи ещё не оценены».
- Все задачи оценены: «Все задачи оценены».
- Ошибка: «Не удалось загрузить итоги сессии. Попробуйте ещё раз».

## 9. Предлагаемый технический вариант

Этот раздел не является обязательным техническим решением. Разработчики вправе выбрать собственную реализацию, если она удовлетворяет требованиям и критериям приёмки.

- Итоги могут быть получены из сервера по идентификатору сессии, созданному в S1-01.
- Для каждой задачи может отображаться сохранённый итоговый SP из S1-05.
- Неприменимые показатели могут отображаться как прочерк без расчёта.
- Экран итогов может быть доступен после подтверждения последней задачи, а также из лобби.
- Для возврата к оценке может использоваться первая неоценённая задача в очереди.

## 10. Решённые продуктовые решения

- Итоги формируются на основе реально сохранённых итоговых SP.
- Для каждой задачи отображаются порядковый номер, ID, заголовок и итоговый SP.
- Если задача не оценена, вместо итогового SP отображается прочерк.
- Неприменимые к одиночной оценке показатели отображаются прочерками.
- После подтверждения последней задачи Host переходит к итогам сессии.
- Итоги сохраняются на сервере и доступны после обновления страницы.
- Host может вернуться к оценке неоценённых задач.
- В S1-06 участвует только Host.

## 11. Открытые вопросы

Открытых продуктовых вопросов, влияющих на реализацию S1-06 и не согласованных ранее, нет.

## 12. Что не входит в S1-06

- Подключение Participant по коду или ссылке.
- Голоса Participant.
- Таймер и продление раунда.
- Специальные карты.
- Исторические эталоны.
- Комментарии.
- Расчёт и отображение многопользовательской статистики.
- Переголосование.
- Управление очередью.
- Экспорт CSV, Excel и интеграция с YouTrack.
- Управление ролями, завершение сессии и удаление сессии.
