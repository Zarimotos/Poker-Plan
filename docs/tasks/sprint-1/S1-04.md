# ТЗ: S1-04 · Просмотр текущей задачи и выбор SP ведущим

**Статус:** рабочее ТЗ для разработки  
**Спринт:** 1 — «Скелет продукта»  
**Целевой уровень:** L2 — минимально работающая функция  
**Перенос:** Нет — необходимая часть оценки  
**Ответственный за продуктовые решения:** тимлид (PM/PO)  
**Ответственные за реализацию:** тимлид и разработчики  

## 1. Основная идея

Host видит сведения текущей задачи из серверной очереди и может выбрать одну карту SP из доступного набора. Выбор карты является предварительным действием Host перед подтверждением итогового SP в S1-05.

В S1-04 доступны числовые карты по шкале Фибоначчи, а также специальные карты «?» и «Кофе-брейк». Карта «?» означает, что Host пока не знает ответ и оценку нужно продолжить позже. Карта «Кофе-брейк» означает паузу в оценке текущей задачи. Ни одна из специальных карт не фиксирует итоговый SP и не завершает сессию.

Участники, таймер, исторические эталоны и расчёт статистики не входят в эту задачу.

## 2. Пользовательский сценарий

1. Host находится в лобби сессии с непустой очередью задач.
2. Host переходит к оценке первой задачи.
3. Система отображает сведения текущей задачи из серверной очереди.
4. Host видит доступный набор карт SP.
5. Host выбирает одну карту SP.
6. Система показывает выбранный вариант как предварительный выбор.
7. Host может изменить выбор до подтверждения итогового SP.
8. Если Host выбрал числовую карту, он может подтвердить итоговый SP в рамках S1-05.
9. Если Host выбрал «?», оценка задачи остаётся незавершённой и должна быть продолжена позже.
10. Если Host выбрал «Кофе-брейк», оценка текущей задачи ставится на паузу.
11. Если текущая задача последняя и Host подтвердил числовое значение, Host переходит к итогам сессии в рамках S1-06.

## 3. Требования к поведению

### 3.1. Отображение текущей задачи

- Host должен видеть сведения задачи, которая является текущей в серверной очереди.
- По умолчанию текущей считается первая неоценённая задача в очереди.
- Для текущей задачи должны отображаться как минимум:
  - ID задачи;
  - заголовок задачи;
  - позиция задачи в очереди.
- Допустимо отображать дополнительные сведения, если они были импортированы:
  - описание задачи;
  - ссылка YouTrack;
  - дополнительные характеристики задачи.
- Если сведения задачи не удалось получить, Host должен увидеть понятное сообщение об ошибке.

### 3.2. Выбор карты SP

- Host может выбрать одну карту SP из доступного набора.
- Одновременно может быть выбрана только одна карта.
- Выбор карты должен быть наглядно отмечен в интерфейсе.
- До подтверждения итогового SP выбор карты является локальным предварительным состоянием.
- Host может изменить выбранную карту до подтверждения итогового SP.
- Если Host не выбрал карту, подтверждение итогового SP в S1-05 не должно быть доступно.

### 3.3. Доступный набор карт

- В S1-04 используются числовые карты по шкале Фибоначчи:
  - 0;
  - 0.5;
  - 1;
  - 2;
  - 3;
  - 5;
  - 8;
  - 13;
  - 20;
  - 40;
  - 100.
- Также доступны специальные карты:
  - «?»;
  - «Кофе-брейк».
- Карта «?» означает: «Не знаю, нужно позже ответить».
- Карта «Кофе-брейк» означает паузу в оценке текущей задачи.
- Специальные карты не являются числовыми значениями SP.
- Специальные карты не позволяют подтвердить итоговый SP.
- Специальные карты не позволяют завершить сессию.
- Набор карт должен быть одинаковым для всех задач в рамках сессии.

### 3.4. Поведение карты «?»

- При выборе «?» Host может сохранить предварительный выбор, но не может подтвердить итоговый SP.
- Карта «?» означает, что оценка задачи должна быть продолжена позднее.
- Карта «?» не фиксирует итоговый SP.
- Карта «?» не завершает сессию.
- Карта «?» не позволяет перейти к следующей задаче через основной сценарий оценки.
- Задача с выбранной картой «?» остаётся неоценённой.

### 3.5. Поведение карты «Кофе-брейк»

- При выборе «Кофе-брейк» Host может поставить оценку текущей задачи на паузу.
- Карта «Кофе-брейк» не фиксирует итоговый SP.
- Карта «Кофе-брейк» не завершает сессию.
- Карта «Кофе-брейк» не позволяет перейти к следующей задаче через основной сценарий оценки.
- После «Кофе-брейка» Host должен иметь возможность вернуться к оценке текущей задачи.
- В S1-04 не требуется определять точный сценарий возобновления после паузы; он уточняется отдельно.

### 3.6. Переход между задачами

- Host может перейти к следующей задаче только после подтверждения числового итогового SP текущей задачи.
- Специальные карты «?» и «Кофе-брейк» не являются подтверждением итогового SP.
- Специальные карты не позволяют перейти к следующей задаче через основной сценарий оценки.
- Подтверждение и сохранение итогового SP реализуются в S1-05.
- Если текущая задача последняя, после подтверждения числового итогового SP Host должен перейти к итогам сессии в рамках S1-06.

## 4. Обязательные данные

Для текущей задачи должны отображаться как минимум:

- ID задачи.
- Заголовок задачи.
- Позиция задачи в очереди.

Для выбора SP должны быть доступны:

- Набор числовых карт по шкале Фибоначчи.
- Специальные карты «?» и «Кофе-брейк».
- Возможность выбрать одну карту.
- Возможность изменить выбор до подтверждения.
- Визуальное обозначение выбранной карты.

## 5. Ограничения и правила

- Оценивает задачу только Host.
- Participant не входит в S1-04.
- Доступен только один предварительный выбор карты SP.
- Таймер не реализуется.
- Исторические эталоны не отображаются.
- Комментарии не реализуются.
- Статистика голосов не рассчитывается.
- Переголосование не реализуется.
- Итоговый SP не сохраняется в рамках S1-04; это задача S1-05.
- Host не может перейти к следующей задаче до подтверждения числового итогового SP.
- Специальные карты не позволяют подтвердить итоговый SP.
- Специальные карты не позволяют завершить сессию.

## 6. Ошибки и состояния

### 6.1. Ошибка загрузки задачи

- Если текущую задачу не удалось загрузить, отображается понятное сообщение об ошибке.
- Host должен иметь возможность повторить загрузку задачи.
- При ошибке не должны отображаться вымышленные или устаревшие данные задачи.

### 6.2. Ошибка выбора карты

- Если выбор карты не удалось зафиксировать в интерфейсе, Host должен увидеть понятное сообщение об ошибке.
- После ошибки Host должен иметь возможность повторить выбор.
- Ошибка выбора не должна приводить к подтверждению итогового SP.

### 6.3. Отсутствие выбранной карты

- Если Host не выбрал карту, кнопка подтверждения итогового SP должна быть недоступна.
- Система должна показывать подсказку: «Выберите карту SP».

### 6.4. Попытка подтвердить специальную карту

- Если Host выбрал «?», подтверждение итогового SP недоступно.
- Если Host выбрал «Кофе-брейк», подтверждение итогового SP недоступно.
- Система должна показать понятную подсказку, что для подтверждения нужна числовая карта SP.

### 6.5. Ошибка перехода

- Если переход к следующей задаче невозможен, Host должен увидеть понятное сообщение об ошибке.
- Если текущая задача не найдена, отображается сообщение: «Задача не найдена».
- Если сессия недоступна, отображается сообщение: «Сессия временно недоступна».

## 7. Критерии приёмки

### AC-1. Отображение текущей задачи

**Дано:** В очереди есть хотя бы одна неоценённая задача.  
**Когда:** Host переходит к оценке.  
**Тогда:** отображаются ID, заголовок и позиция первой неоценённой задачи.

### AC-2. Отображение набора карт

**Дано:** Host находится на экране оценки текущей задачи.  
**Когда:** экран загружен.  
**Тогда:** отображаются числовые карты Фибоначчи и специальные карты «?» и «Кофе-брейк».

### AC-3. Выбор одной карты

**Дано:** Host находится на экране оценки текущей задачи.  
**Когда:** Host выбирает одну карту SP.  
**Тогда:** выбранная карта визуально отмечена, а остальные карты не отмечены как выбранные.

### AC-4. Изменение выбора

**Дано:** Host уже выбрал карту SP.  
**Когда:** Host выбирает другую карту до подтверждения итогового SP.  
**Тогда:** новая карта становится выбранным предварительным значением.

### AC-5. Блокировка подтверждения без числового выбора

**Дано:** Host не выбрал числовую карту SP.  
**Когда:** Host пытается подтвердить итоговый SP.  
**Тогда:** подтверждение недоступно, а система показывает подсказку о необходимости выбрать числовую карту.

### AC-6. Карта «?» не завершает оценку

**Дано:** Host выбрал карту «?».  
**Когда:** Host пытается подтвердить итоговый SP.  
**Тогда:** подтверждение недоступно, а задача остаётся неоценённой.

### AC-7. Карта «Кофе-брейк» не завершает сессию

**Дано:** Host выбрал карту «Кофе-брейк».  
**Когда:** Host пытается подтвердить итоговый SP.  
**Тогда:** подтверждение недоступно, а сессия не завершается.

### AC-8. Возврат после «Кофе-брейка»

**Дано:** Host выбрал карту «Кофе-брейк».  
**Когда:** Host возвращается к оценке текущей задачи.  
**Тогда:** Host может продолжить оценку задачи.

### AC-9. Переход после подтверждения числового SP

**Дано:** Host подтвердил числовый итоговый SP текущей задачи.  
**Когда:** система обрабатывает подтверждение.  
**Тогда:** Host может перейти к следующей задаче либо к итогам, если текущая задача была последней.

### AC-10. Ошибка загрузки задачи

**Дано:** Сервер недоступен или произошла ошибка при получении задачи.  
**Когда:** Host открывает экран оценки.  
**Тогда:** отображается понятное сообщение об ошибке, а Host может повторить загрузку.

## 8. Предлагаемый вариант интерфейса

Этот раздел — предложение для согласования, а не обязательное техническое решение.

### 8.1. Экран оценки задачи

- Заголовок: «Оценка задачи».
- Прогресс: «Задача N из M».
- Блок с ID задачи.
- Заголовок задачи.
- Блок с описанием задачи, если оно было импортировано.
- Ссылка YouTrack, если она была импортирована.
- Панель карт SP:
  - 0;
  - 0.5;
  - 1;
  - 2;
  - 3;
  - 5;
  - 8;
  - 13;
  - 20;
  - 40;
  - 100;
  - «?»;
  - «Кофе-брейк».
- Подсказка: «Выберите карту SP».
- Кнопка «Подтвердить» — недоступна до выбора числовой карты.
- Кнопка «Назад в лобби».

### 8.2. Состояния экрана

- Загрузка: «Загружаем задачу…».
- Без выбора: «Выберите карту SP».
- Выбрана числовая карта: отображается выбранное значение SP.
- Выбрана «?»: «Оценка будет продолжена позже».
- Выбран «Кофе-брейк»: «Оценка поставлена на паузу».
- Ошибка загрузки: «Не удалось загрузить задачу. Попробуйте ещё раз».

## 9. Предлагаемый технический вариант

Этот раздел не является обязательным техническим решением. Разработчики вправе выбрать собственную реализацию, если она удовлетворяет требованиям и критериям приёмки.

- Текущая задача может определяться как первая неоценённая задача в серверной очереди.
- Сведения задачи могут быть получены по идентификатору сессии и позиции либо идентификатору задачи.
- Предварительный выбор карты может храниться в локальном состоянии клиента до подтверждения.
- Подтверждение итогового SP может быть реализовано в S1-05 через отдельное серверное действие.
- Специальные карты могут быть представлены как отдельные типы выбора, не являющиеся числовым значением SP.
- Набор карт может быть задан конфигурацией интерфейса или сервера; выбор способа остаётся инженерным решением.
