# ТЗ: PRE-01 — Формат данных задач для импорта из CSV

**Задача:** определить финальный формат CSV для импорта задач в Planning Poker, правила валидации, сопоставление с внутренней моделью `Task` и требования к интерфейсу импорта. Результат нужен до реализации S1-02 «Импорт задач из CSV с предпросмотром и подтверждением».

**Владелец задачи:** системный аналитик.

**Исполнители:** системный аналитик, дизайнер, 2 фронтенд-разработчика, бэкенд-разработчик / DevOps.

**Приоритет:** высокий — без PRE-01 нельзя корректно начать S1-02.

## Цель и результат

По итогам задачи команда получает согласованный документ и артефакты, позволяющие начать разработку импорта без уточнений в процессе:

- спецификация CSV: поля, типы, обязательность, ограничения, значения по умолчанию;
- правила валидации файла и отдельных строк;
- сопоставление CSV → `Task` и анализ совместимости с экспортом YouTrack;
- примеры корректного и ошибочного CSV;
- шаблон CSV для скачивания;
- требования к модальному окну импорта и обработке ошибок;
- согласованное решение: где выполняется парсинг и валидация — на клиенте, сервере или комбинированно.

PRE-01 не включает реализацию импорта, подключение YouTrack, импорт Excel и редактирование задач после загрузки.

## Границы

| Входит | Не входит |
|---|---|
| Формат CSV и перечень полей | Реализация кнопки/загрузки файла |
| Валидация файла и строк | Прямая интеграция с YouTrack |
| Маппинг CSV → `Task` | Импорт Excel |
| Правила обработки ошибок | Редактирование импортированных задач |
| Требования к предпросмотру | Полный API и архитектура приложения |
| Шаблон CSV | Экспорт CSV и статистика |

Формат нужен именно для S1-02: Host выбирает CSV, видит распознанные задачи, подтверждает или отменяет импорт, после чего задачи сохраняются на сервере.

## Требования к CSV

Аналитик фиксирует окончательный вариант, но для старта рекомендуется следующая базовая схема:

| Поле | Тип | Обязательное | Ограничение / значение по умолчанию |
|---|---|---|---|
| `id` | строка | Нет | Уникальный идентификатор; если пусто, генерирует система |
| `title` | строка | Да | Не пустое; максимум 200 символов |
| `description` | текст | Нет | Обычный текст; лимит определяет аналитик |
| `priority` | enum | Нет | `Critical`, `High`, `Medium`, `Low`; пусто = `Medium` |
| `youtrack_url` | URL | Нет | Корректный URL или пустое значение |
| `labels` | строка | Нет | Список через запятую |
| `estimate` | число | Нет | Только если задача уже оценена; значение должно соответствовать выбранной шкале |

Общие требования:

- кодировка UTF-8;
- первая строка — заголовки колонок;
- разделитель — запятая;
- значения с запятыми, кавычками или переносами строк заключаются в двойные кавычки;
- пустые необязательные поля допустимы;
- дубликаты заголовков колонок не допускаются.

## Валидация

Файл блокируется целиком, если:

- файл пустой;
- это не читаемый CSV;
- кодировка не UTF-8;
- отсутствует обязательная колонка `title`;
- заголовки колонок дублируются.

Строка помечается ошибкой, если:

- `title` пустой;
- `title` длиннее лимита;
- `priority` не входит в допустимый список;
- `youtrack_url` не является валидным URL;
- `estimate` не соответствует допустимой шкале;
- строка содержит некорректное число символов/разделителей и не может быть распознана.

Необходимо заранее выбрать и зафиксировать поведение:

- **Вариант A:** при любой ошибке в строке импорт запрещается до исправления файла.
- **Вариант B:** пользователь видит ошибки и может импортировать только отмеченные корректные строки.
- **Вариант C:** ошибочные строки автоматически пропускаются, а пользователь получает отчёт.

Рекомендуемый вариант для первого спринта — **A**: проще реализовать, легче тестировать и достаточно для L2-сценария. Финальное решение принимает системный аналитик.

## Интерфейс импорта

Требования должны опираться на модальное окно импорта из спецификации: drag-and-drop зона, ссылка «Скачать шаблон», таблица предпросмотра с ID, заголовком, приоритетом и чекбоксами, кнопки «Импортировать N задач» и «Отмена».

Дизайнер и фронтенд должны получить описание следующих состояний:

- файл не выбран;
- файл читается / загружается;
- файл невалиден;
- в файле есть ошибки в строках;
- успешный предпросмотр;
- подтверждение импорта;
- отмена импорта;
- ошибка сохранения на сервере.

Для пустого или невалидного CSV используется сообщение: «Не удалось распарсить файл. Проверьте формат» со ссылкой на шаблон.

## Распределение по ролям

### Системный аналитик — владелец PRE-01

**Задача:** подготовить и согласовать аналитическую основу импорта.

- Определить окончательный перечень полей CSV, их типы, обязательность и лимиты.
- Зафиксировать кодировку, разделитель, правила кавычек и структуру заголовков.
- Описать валидацию файла и отдельных строк.
- Выбрать стратегию обработки ошибок: блокировка импорта, пропуск строк или выборочный импорт.
- Описать маппинг каждого поля CSV в `Task`.
- Проанализировать экспорт YouTrack и определить обязательные преобразования значений.
- Подготовить примеры: корректный CSV, пустой файл, файл с неверной структурой, файл с ошибками в отдельных строках.
- Согласовать тексты ошибок и правила предпросмотра с дизайнером и фронтендом.
- Передать финальную спецификацию бэкенду и фронтенду.
- Принять результат перед началом S1-02.

**Переход по файлам в репозитории на спецификацию ТЗ:** [`docs/specs/csv-import-specification.md`](docs/specs/csv-import-specification.md)

**Результат аналитика:** документ спецификации CSV + примеры файлов + согласованные правила ошибок.

### Дизайнер

**Задача:** подготовить UX/UI-решение для импорта и отображения ошибок.

- Доработать макет модалки импорта для всех состояний из раздела «Интерфейс импорта».
- Спроектировать отображение ошибок: общая ошибка файла, ошибки по строкам, подсветка проблемных полей.
- Определить поведение таблицы предпросмотра: какие колонки видны, как отображается длинный заголовок/описание, как работают чекбоксы.
- Согласовать с аналитиком тексты ошибок и с фронтендом — техническую реализуемость состояний.
- Передать макеты, состояния и тексты в общую задачу S1-02.

**Результат дизайнера:** макеты/спецификация UI импорта + скачиваемый шаблон CSV.

### Фронтенд-разработчик 1

**Задача:** требования и техническое решение для загрузки и разбора файла.

- Совместно с бэкендом определить, где выполняется парсинг CSV: на клиенте или на сервере.
- Если парсинг на клиенте: описать библиотеку/подход, лимит размера файла, обработку кодировки и ошибок чтения.
- Если парсинг на сервере: описать передачу файла, состояния загрузки и формат ответа с ошибками.
- Подготовить требования к drag-and-drop, выбору файла вручную и кнопке «Скачать шаблон».
- Описать клиентскую валидацию до отправки на сервер, если она предусмотрена.
- Согласовать с фронтенд-разработчиком 2 разделение работ по UI и логике.

**Результат:** техническое предложение по загрузке/парсингу + перечень клиентских состояний и ошибок.

### Фронтенд-разработчик 2

**Задача:** требования к предпросмотру, подтверждению и отображению результатов импорта.

- Описать структуру таблицы предпросмотра и правила отображения полей `id`, `title`, `priority`.
- Определить поведение чекбоксов: выбор строк, счётчик «Импортировать N задач», поведение при ошибках.
- Описать подтверждение импорта, отмену и обновление очереди задач в лобби.
- Подготовить требования к toast-уведомлениям и inline-ошибкам.
- Согласовать с дизайнером макеты и с фронтенд-разработчиком 1 — контракт данных для предпросмотра.

**Результат:** требования к UI предпросмотра и подтверждения + согласованный формат данных для отображения.

### Бэкенд-разработчик / DevOps

**Задача:** определить серверную обработку CSV и требования к хранению задач.

- Подтвердить или скорректировать решение о месте парсинга: клиент, сервер или гибрид.
- Определить серверные правила валидации, чтобы они не расходились с клиентскими.
- Описать маппинг CSV → `Task`, включая генерацию `id`, значения по умолчанию и нормализацию данных.
- Определить формат ошибок API: код ошибки, сообщение, номер строки, поле.
- Определить лимиты: максимальный размер файла, максимальное число задач в одном импорте, таймаут обработки.
- Описать требования к логированию ошибок импорта.
- Если парсинг серверный — подготовить требования к окружению, зависимостям и конфигурации; развёртывание и CI в PRE-01 не входят.
- Дать заключение о реализуемости формата и маппинга до передачи задачи в разработку.

**Результат:** серверные правила валидации + контракт ошибок + подтверждённый маппинг CSV → `Task`.

## Порядок работы

1. Аналитик готовит черновик формата CSV, правил валидации и маппинга — 1–2 дня.
2. Бэкенд проверяет реализуемость, определяет место парсинга и формат ошибок — параллельно, 1 день.
3. Фронтенды оценивают клиентскую часть, загрузку, предпросмотр и подтверждение — параллельно, 1 день.
4. Дизайнер готовит состояния модалки и шаблон CSV — параллельно, 1–2 дня.
5. Аналитик проводит согласование, фиксирует финальные решения и публикует ТЗ — 0,5 дня.
6. Тимлид / аналитик принимает PRE-01 и переводит S1-02 в готовность к разработке.

## Definition of Done

- Утверждён документ с полным описанием CSV-формата.
- Описаны все правила валидации файла и строк.
- Есть примеры корректного и ошибочного CSV.
- Описан маппинг CSV → `Task`, включая значения по умолчанию.
- Определено, где выполняется парсинг и валидация.
- Описан формат ошибок для UI и API.
- Подготовлены требования ко всем состояниям модалки импорта.
- Дизайнер, оба фронтенда и бэкенд подтвердили реализуемость.
- Аналитик принял результат; PRE-01 не блокирует S1-02.

## Риски

- Расхождение клиента и сервера в валидации — устраняется единым документом правил и форматом ошибок.
- Сложный экспорт YouTrack — может потребовать нормализации полей; в PRE-01 фиксируем только преобразования, без интеграции.
- Неопределённость по частичному импорту — лучше выбрать простой вариант A для первого спринта.
- Длинные описания и спецсимволы в CSV — обязательно проверить кавычки, переносы строк, запятые и UTF-8.
- Перегрузка единственного бэкенда/DevOps — его участие в PRE-01 должно быть ограничено техническими решениями, без реализации импорта.
