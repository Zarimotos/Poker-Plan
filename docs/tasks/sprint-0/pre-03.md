# ТЗ: PRE-03 — Модель данных и интерфейсы взаимодействия для первого спринта

**Задача:** определить минимальные сущности `Session`, `Task`, `Estimate`, их связи, жизненные циклы и API-контракты для первого пользовательского сценария: создание сессии → предпросмотр CSV → подтверждённый импорт CSV → очередь → оценка → подтверждение SP → итоги. Результат является входом для S1-01–S1-06.

**Владелец задачи:** системный аналитик.

**Основные исполнители:** системный аналитик, бэкенд-разработчик / DevOps, 2 фронтенд-разработчика.

**Участник:** дизайнер — проверяет, что контракт данных покрывает все экраны и UI-состояния.

**Приоритет:** высокий; PRE-03 зависит от PRE-01 и PRE-02 и блокирует S1-01, S1-02 и S1-05.

## Цель

По итогам задачи команда получает единый контракт данных и API, достаточный для реализации первого вертикального среза. Сервер должен быть источником истины: сессия, импортированные задачи, выбранный SP и подтверждённый итоговый SP сохраняются на сервере и восстанавливаются после обновления страницы.

**Ожидаемый результат по плану:** описаны `Session`, `Task`, `Estimate` и их связи; определены жизненный цикл сессии и задачи; подготовлены минимальные API-контракты для создания и получения сессии, предпросмотра и подтверждённого импорта CSV, очереди, оценки и итогов; явно выделены данные, сохраняемые на сервере, и временные данные CSV-предпросмотра.

## Границы

| Входит | Не входит |
|---|---|
| Сущности `Session`, `Task`, `Estimate` | Полная модель всех будущих функций |
| Связи между сущностями | Выбор СУБД и детальная схема БД, если это не необходимо для контракта |
| Жизненный цикл сессии и задачи | Полная state machine всех будущих сценариев |
| API для первого сценария, включая CSV preview | WebSocket-события и многопользовательская синхронизация |
| Форматы запросов и ответов | Реализация эндпоинтов |
| Коды, структура ошибок и разделение ошибок по статусу сессии | Полная обработка редких исключений |
| Правила восстановления состояния | Интеграция YouTrack, Excel, экспорт CSV |
| Правила распознавания русских и английских CSV-заголовков | Полная локализация интерфейса импорта |

Контракт должен покрывать только операции первого пользовательского сценария; полный будущий API и технические детали реализации не требуются.

## Минимальная модель данных

### Session

| Поле | Тип | Обязательное | Назначение |
|---|---|---|---|
| `id` | UUID / строка | Да | Серверный идентификатор сессии |
| `room_code` | строка | Да | Код сессии для URL и последующего подключения участников |
| `title` | строка | Да | Название сессии |
| `host_name` | строка | Да | Имя ведущего |
| `scale` | enum | Да | Выбранная шкала оценок |
| `status` | enum | Да | `CREATED`, `TASKS_IMPORTED`, `IN_PROGRESS`, `COMPLETED` |
| `current_task_id` | UUID / строка | Нет | Текущая задача в очереди |
| `created_at` | datetime | Да | Время создания |
| `updated_at` | datetime | Да | Время последнего изменения |

Для первого спринта достаточно одного Host; поля участников, ролей и подключения закладываются как направление расширения, но не должны усложнять контракт S1.

### Жизненный цикл сессии

Допустимые статусы:

| Статус | Значение |
|---|---|
| `CREATED` | Сессия создана, задачи не импортированы |
| `TASKS_IMPORTED` | В сессию импортирована хотя бы одна задача |
| `IN_PROGRESS` | Начата оценка задач |
| `COMPLETED` | Все импортированные задачи оценены |

Допустимые переходы:

```text
CREATED → TASKS_IMPORTED
TASKS_IMPORTED → IN_PROGRESS
IN_PROGRESS → COMPLETED
```

| Переход | Триггер | API |
|---|---|---|
| `CREATED → TASKS_IMPORTED` | Успешный импорт хотя бы одной задачи | `POST /api/v1/sessions/{sessionId}/csv/import` |
| `TASKS_IMPORTED → IN_PROGRESS` | Первый запрос текущей задачи | `GET /api/v1/sessions/{sessionId}/tasks/current` |
| `IN_PROGRESS → COMPLETED` | Подтверждение оценки последней задачи | `POST /api/v1/sessions/{sessionId}/tasks/{taskId}/estimate` |

Чтение очереди через `GET /api/v1/sessions/{sessionId}/tasks` не изменяет статус сессии.

Попытка выполнить недопустимый переход возвращает `409 Conflict` с кодом `INVALID_SESSION_STATE`.

### Task

| Поле | Тип | Обязательное | Назначение |
|---|---|---|---|
| `id` | UUID / строка | Да | Серверный идентификатор задачи |
| `session_id` | UUID / строка | Да | Ссылка на сессию |
| `external_id` | строка | Да | Идентификатор задачи из CSV или внешней системы |
| `title` | строка | Да | Заголовок задачи |
| `description` | текст | Нет | Описание задачи |
| `youtrack_url` | URL | Нет | Ссылка на YouTrack |
| `priority` | enum | Нет | `Critical`, `High`, `Medium`, `Low` |
| `components` | массив строк | Нет | Компоненты задачи |
| `affected_scenarios` | массив строк | Нет | Затронутые сценарии |
| `notes` | текст | Нет | Заметки |
| `tags` | массив строк | Нет | Теги |
| `initial_story_points` | число / enum | Нет | Исходный SP из CSV |
| `final_story_points` | число / enum | Нет | Подтверждённый итоговый SP |
| `position` | integer | Да | Позиция в очереди |
| `status` | enum | Да | `PENDING`, `ESTIMATING`, `ESTIMATED` |
| `created_at` | datetime | Да | Время создания |
| `updated_at` | datetime | Да | Время последнего изменения |

Поля `row_number`, `is_valid` и `errors` не входят в модель `Task`: они относятся только к временному результату `CsvTaskPreview` и не сохраняются в БД.

Поля `labels`, вложения и расширенные атрибуты YouTrack в первый контракт не включаются, если они не нужны для обязательного сценария.

Маппинг CSV → `CsvTaskPreview` → `Task` должен быть расширяемым: добавление новой колонки CSV или нового поля задачи не должно требовать изменений в нескольких несвязанных слоях приложения.

### Жизненный цикл задачи

```text
PENDING → ESTIMATING → ESTIMATED
```

| Переход | Триггер |
|---|---|
| `PENDING → ESTIMATING` | Задача выбрана как текущая для оценки |
| `ESTIMATING → ESTIMATED` | Host подтвердил итоговый SP |

Повторная оценка задачи в первом спринте не поддерживается. Попытка повторно подтвердить SP возвращает `409 Conflict` с кодом `TASK_ALREADY_ESTIMATED`.

### Estimate

| Поле | Тип | Обязательное | Назначение |
|---|---|---|---|
| `id` | UUID / строка | Да | Идентификатор оценки |
| `task_id` | UUID / строка | Да | Ссылка на задачу |
| `session_id` | UUID / строка | Да | Ссылка на сессию |
| `selected_sp` | число / enum | Да | SP, выбранный Host до подтверждения |
| `final_sp` | число / enum | Нет | Подтверждённый итоговый SP |
| `finalized_at` | datetime | Нет | Время фиксации итогового SP |
| `created_at` | datetime | Да | Время создания |

В первом спринте Host выбирает числовую карту и вручную подтверждает итоговый SP; оценка должна сохраняться на сервере. До подтверждения `final_sp` может быть `null`. После подтверждения оценка становится неизменяемой в рамках первого спринта: повторная фиксация возвращает `409 Conflict` с кодом `ESTIMATE_ALREADY_FINALIZED`.

## Связи

```text
Session 1 ──< Task
Session 1 ──< Estimate
Task 1 ────1 Estimate
```

- Одна сессия содержит упорядоченный список задач.
- Одна задача относится к одной сессии.
- Одна задача имеет одну актуальную оценку в рамках первого сценария.
- Итоговый SP хранится в `Estimate`, а не вычисляется на клиенте.

## CSV-импорт

Импорт состоит из двух шагов:

1. `POST /api/v1/sessions/{sessionId}/csv/preview` — разбор файла без сохранения задач.
2. `POST /api/v1/sessions/{sessionId}/csv/import` — сохранение выбранных корректных задач.

### CsvTaskPreview

`CsvTaskPreview` — временное представление строки CSV. Оно не сохраняется в БД и содержит:

- данные строки;
- `rowNumber`;
- `isValid`;
- `errors`.

### Семантика ошибок preview

- `tasks[].isValid` — признак того, что строка может быть импортирована.
- `tasks[].errors` — ошибки конкретной строки CSV.
- Верхнеуровневый `errors` — ошибки уровня всего файла: формат, кодировка, отсутствие обязательной колонки, лимиты размера или количества строк.

Ошибка отдельной строки не делает весь запрос ошибочным: API возвращает `200 OK`, а Host выбирает только корректные задачи.

### Локализация заголовков CSV

Сервис должен распознавать заголовки колонок на русском и английском языках.

Правила:

- регистр заголовков не учитывается;
- начальные и конечные пробелы игнорируются;
- поддерживаются заранее определённые русские и английские варианты заголовков;
- в API и ошибках используется каноническое имя поля, например `components`;
- исходное название колонки передаётся в `sourceColumn`.

Примеры маппинга:

| Каноническое поле API | Русский заголовок | Английский заголовок |
|---|---|---|
| `externalId` | `ID задачи`, `Идентификатор` | `Task ID`, `External ID` |
| `title` | `Название`, `Задача` | `Title`, `Summary` |
| `description` | `Описание` | `Description` |
| `youtrackUrl` | `Ссылка`, `URL` | `URL`, `Link` |
| `priority` | `Приоритет` | `Priority` |
| `components` | `Компоненты` | `Components` |
| `affectedScenarios` | `Затронутые сценарии` | `Affected Scenarios` |
| `notes` | `Заметки`, `Примечания` | `Notes` |
| `tags` | `Теги`, `Метки` | `Tags` |
| `initialStoryPoints` | `Исходные SP` | `Initial Story Points` |

Пример ошибки строки:

```json
{
  "rowNumber": 4,
  "field": "components",
  "sourceColumn": "Компоненты",
  "value": "BACKEND",
  "code": "INVALID_COMPONENT",
  "message": "Строка 4: указан недопустимый компонент „BACKEND“."
}
```

## Минимальный API

Базовый префикс API: `/api/v1`.

| Операция | Метод и путь | Назначение |
|---|---|---|
| Создать сессию | `POST /api/v1/sessions` | Создаёт `Session` в статусе `CREATED` |
| Получить сессию | `GET /api/v1/sessions/{sessionId}` | Возвращает сессию в любом статусе, включая `COMPLETED` |
| Предпросмотр CSV | `POST /api/v1/sessions/{sessionId}/csv/preview` | Разбирает CSV, возвращает валидные и невалидные строки, не изменяет очередь |
| Импортировать задачи | `POST /api/v1/sessions/{sessionId}/csv/import` | Сохраняет выбранные корректные задачи и переводит сессию в `TASKS_IMPORTED` |
| Получить очередь | `GET /api/v1/sessions/{sessionId}/tasks` | Возвращает упорядоченный список сохранённых задач |
| Получить текущую задачу | `GET /api/v1/sessions/{sessionId}/tasks/current` | Возвращает задачу для оценки; первый вызов переводит сессию в `IN_PROGRESS` |
| Подтвердить итоговый SP | `POST /api/v1/sessions/{sessionId}/tasks/{taskId}/estimate` | Фиксирует итоговый SP, возвращает следующую задачу или признак завершения |
| Получить итоги | `GET /api/v1/sessions/{sessionId}/summary` | Возвращает итоги; доступен только в статусе `COMPLETED` |

Контракт каждого эндпоинта должен включать: метод, путь, параметры, тело запроса, тело ответа, коды успеха и ошибок, пример JSON.

Отдельный эндпоинт `estimate/finalize` в первом спринте не вводится: выбор и подтверждение итогового SP выполняются одним запросом `POST /estimate`.

## Формат ошибок

Единый формат ответа об ошибке:

```json
{
  "code": "INVALID_STORY_POINTS",
  "message": "Значение Story Points должно быть из шкалы оценки.",
  "details": [
    {
      "field": "storyPoints",
      "value": 7
    }
  ]
}
```

Схема `details`:

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `field` | строка | Нет | Каноническое имя поля API |
| `value` | any | Нет | Переданное значение |
| `sourceColumn` | строка / null | Нет | Исходное название колонки CSV |
| `rowNumber` | integer | Нет | Номер строки CSV |

Минимальный набор кодов:

| Код | Ситуация |
|---|---|
| `VALIDATION_ERROR` | Некорректные данные запроса |
| `SESSION_NOT_FOUND` | Сессия не найдена |
| `INVALID_SESSION_STATE` | Сессия существует, но операция недоступна в текущем статусе |
| `SESSION_NOT_IN_PROGRESS` | Оценка ещё не начата или уже завершена |
| `SESSION_NOT_COMPLETED` | Итоги недоступны, поскольку сессия не завершена |
| `TASK_NOT_FOUND` | Задача не найдена |
| `TASK_ALREADY_ESTIMATED` | Задача уже оценена |
| `INVALID_CSV` | CSV не читается или не соответствует формату |
| `MISSING_REQUIRED_COLUMN` | Отсутствует обязательная колонка CSV |
| `FILE_TOO_LARGE` | Размер CSV превышает лимит |
| `UNSUPPORTED_MEDIA_TYPE` | Загружен не CSV-файл |
| `ESTIMATE_ALREADY_FINALIZED` | Итоговый SP уже подтверждён |
| `INTERNAL_ERROR` | Внутренняя ошибка сервера |

`SESSION_NOT_FOUND` означает только отсутствие сессии. Завершённая сессия остаётся доступной для `GET /sessions/{sessionId}` и `GET /summary`.

Для пустого или невалидного CSV пользователь должен видеть сообщение «Не удалось распарсить файл. Проверьте формат» со ссылкой на шаблон.

## UI-состояния, покрываемые контрактом

Контракт должен обеспечивать данные для состояний:

- создание сессии и ошибки валидации формы;
- лобби с названием, кодом, счётчиком задач и очередью;
- импорт: чтение файла, предпросмотр, подтверждение, отмена, ошибка;
- отображение ошибок конкретной строки CSV отдельно от ошибок уровня файла;
- пустая очередь;
- экран текущей задачи;
- выбор SP и подтверждение;
- переход к следующей задаче;
- завершение последней задачи;
- итоги с фактическими задачами и сохранёнными SP;
- обновление страницы без потери серверных данных.

## Порядок работы

1. Аналитик готовит черновик сущностей, связей, жизненных циклов и перечня API — 0,5–1 день.
2. Бэкенд предлагает точные контракты, валидацию, CSV-маппинг и правила хранения — параллельно, 1 день.
3. Фронтенд 1 описывает клиентский API-слой и состояние — параллельно, 0,5–1 день.
4. Фронтенд 2 сверяет контракт с экранами и переходами — параллельно, 0,5 дня.
5. Дизайнер проверяет UI-полноту — параллельно, 0,5 дня.
6. Аналитик согласовывает финальную версию и публикует документ — 0,5 дня.
7. Команда принимает контракт; S1-01, S1-02 и S1-05 получают готовый DoR.

## Риски

- Расхождение клиента и сервера в типах данных — устраняется единым документом контрактов и примерами JSON.
- Избыточный API — риск потратить время на операции будущих спринтов; ограничиваем контракт первым сценарием.
- Недостаточные данные для UI — устраняется ранней проверкой контракта дизайнером и фронтендом.
- Неопределённость при повторном импорте или повторном подтверждении — необходимо явно описать идемпотентность или запрет повторной операции.
- Жёсткая привязка импорта к текущему набору колонок может замедлить добавление новых полей — устраняется расширяемым маппингом CSV → preview → Task.
- Смешение ошибок строки и ошибок файла усложнит UI — устраняется разделением `tasks[].errors` и верхнеуровневого `errors`.
- Объединение «сессия не найдена» и «сессия завершена» приведёт к некорректным UI-состояниям — устраняется раздельными кодами ошибок.
- Узкое место на бэкенде/DevOps — его участие ограничиваем проектированием контракта и модели, без реализации эндпоинтов в PRE-03.
