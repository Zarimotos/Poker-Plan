# Спецификация импорта задач из CSV

**Задача:** PRE-01 — Определить формат данных задач для импорта из CSV  
**Владелец:** Системный аналитик  
**Связанные задачи:** S1-02 «Импорт задач из CSV с предпросмотром и подтверждением»  
**Статус:** Черновик после учёта ревью PM/PO  

## 1. Цель

Определить правила импорта задач из CSV в Planning Poker: пользовательскую разметку колонок, валидацию, обработку ошибок и преобразование данных во внутреннюю модель `Task`.

Спецификация является основой для реализации S1-02: Host выбирает один CSV-файл, назначает смысл его колонкам, видит список корректных задач до подтверждения, а после подтверждения корректные задачи сохраняются в серверной очереди.

**Вне объёма PRE-01:**

- прямое подключение к YouTrack;
- импорт Excel;
- редактирование задач после импорта;
- автоматическая двусторонняя синхронизация с YouTrack;
- экспорт CSV;
- загрузка нескольких CSV-файлов в рамках одного импорта;
- автоматическое сопоставление колонок по их названиям;
- сохранение шаблонов разметки между сессиями;
- реализация алгоритма рекомендаций по базе эталонов;
- автоматическое создание отсутствующей колонки итоговых SP.

## 2. Основной принцип: разметка колонок

Система не должна требовать фиксированных названий колонок CSV. Названия могут быть локализованы, содержать произвольные символы и иметь разный смысл в разных командах.

Пользователь сам назначает колонкам загруженного файла роли данных Planning Poker. Система использует назначенные роли, а не названия колонок.

### Обязательные роли

| Роль | Обязательность | Назначение |
|---|---|---|
| `TASK_ID` | Да | Внешний идентификатор задачи |
| `TITLE` | Да | Заголовок задачи |
| `FINAL_SP_TARGET` | Да | Колонка, в которую в дальнейшем записываются итоговые SP |

### Необязательные роли

| Роль | Обязательность | Назначение |
|---|---|---|
| `DESCRIPTION` | Нет | Описание задачи |
| `YOUTRACK_URL` | Нет | Ссылка на задачу в YouTrack |
| `PRIORITY` | Нет | Приоритет задачи |
| `NOTES` | Нет | Комментарии к задаче |
| `TAGS` | Нет | Теги задачи |
| `ATTRIBUTE` | Нет | Произвольная дополнительная характеристика |

### Правила разметки

- Обязательные роли `TASK_ID`, `TITLE` и `FINAL_SP_TARGET` должны быть назначены до подтверждения импорта.
- Каждая из обязательных ролей назначается ровно одной колонке.
- Одна колонка может быть назначена только одной роли.
- Роль `ATTRIBUTE` может быть назначена нескольким колонкам.
- Неопознанные колонки, которым не назначена роль, не являются ошибкой.
- Отсутствие необязательной колонки не является ошибкой и не требует предупреждения.
- Разметка сохраняется в рамках сессии и может использоваться при будущем экспорте.
- Разметка не изменяет исходный CSV-файл на устройстве пользователя.

## 3. Требования к файлу

| Параметр | Значение |
|---|---|
| Формат | CSV |
| Расширение | `.csv` |
| Кодировка | UTF-8, желательно с BOM |
| Разделитель полей | `,` |
| Разделитель значений в multi-value полях | `;` |
| Экранирование | Двойные кавычки `"` |
| Кавычка внутри значения | Удваивается: `""` |
| Переносы строк | Допустимы внутри значений, заключённых в кавычки |
| Первая строка | Обязательная строка заголовков |
| Заголовки колонок | Отображаются пользователю в исходном виде |
| Пробелы в заголовках | Обрезаются по краям при отображении |
| Пустые строки | Игнорируются |
| Минимальное количество задач | 1 |
| Максимальное количество задач | 200 — требуется согласовать |
| Максимальный размер файла | 2 МБ — требуется согласовать |

**Правила заголовков:**

- Заголовки могут быть на любом языке и содержать любые допустимые для CSV символы.
- Регистр заголовка сохраняется при отображении пользователю.
- Регистр заголовка не используется для автоматического определения роли колонки.
- Если две колонки имеют одинаковое отображаемое название, система должна обеспечить однозначный выбор колонки, например с помощью порядкового номера колонки.
- Пустой заголовок колонки не блокирует импорт, если пользователь может однозначно выбрать эту колонку при разметке.
- При замене выбранного CSV-файла ранее созданная разметка не применяется автоматически; пользователь выполняет разметку заново.

## 4. Роли колонок и данные задачи

### 4.1. Роль `TASK_ID`

| Свойство | Значение |
|---|---|
| Поле `Task` | `externalId` |
| Тип | Строка |
| Обязательность роли | Да |
| Ограничения значения | Непустая строка, максимум 50 символов, уникальна в пределах файла |

### 4.2. Роль `TITLE`

| Свойство | Значение |
|---|---|
| Поле `Task` | `title` |
| Тип | Строка |
| Обязательность роли | Да |
| Ограничения значения | 1–200 символов после нормализации |

### 4.3. Роль `FINAL_SP_TARGET`

| Свойство | Значение |
|---|---|
| Поле `Task` | `finalStoryPoints` |
| Тип | Число из шкалы SP |
| Обязательность роли | Да |
| Ограничения значения | Пусто или значение из шкалы SP |

**Правила:**

- Колонка с ролью `FINAL_SP_TARGET` должна существовать в загруженном CSV.
- Значения этой колонки при импорте игнорируются и не считаются исходными оценками текущей сессии.
- Роль колонки — место для будущей записи итоговых SP.
- До подтверждения импорта пользователь должен увидеть предупреждение: новые итоговые SP будут записаны в выбранную колонку поверх существующих значений.
- Если подходящей колонки нет, пользователь вручную добавляет её в конец CSV-файла, сохраняет файл и загружает его повторно.
- Приложение показывает подсказку о ручном добавлении колонки, но не создаёт колонку автоматически.
- Имя добавляемой колонки произвольное; назначение определяет разметка, а не название.

**Пример текста подсказки:**

> Если в вашем CSV-файле нет колонки для итоговой оценки Story Points, добавьте её вручную в конец файла, сохраните изменения и загрузите файл повторно.

### 4.4. Роль `DESCRIPTION`

| Свойство | Значение |
|---|---|
| Поле `Task` | `description` |
| Тип | Многострочный текст |
| Обязательность роли | Нет |
| Ограничения значения | До 10 000 символов; пустое значение допустимо |

### 4.5. Роль `YOUTRACK_URL`

| Свойство | Значение |
|---|---|
| Поле `Task` | `youtrackUrl` |
| Тип | URL |
| Обязательность роли | Нет |
| Ограничения значения | Валидный `http://` или `https://` URL, максимум 2 048 символов; пустое значение допустимо |

### 4.6. Роль `PRIORITY`

| Свойство | Значение |
|---|---|
| Поле `Task` | `priority` |
| Тип | Строка |
| Обязательность роли | Нет |
| Ограничения значения | Определяются правилами конкретной команды; пустое значение допустимо |

Приоритет не должен иметь универсальный фиксированный справочник для всех команд. Если колонке назначена эта роль, правила интерпретации значений должны быть согласованы отдельно.

### 4.7. Роль `NOTES`

| Свойство | Значение |
|---|---|
| Поле `Task` | `notes` |
| Тип | Многострочный текст |
| Обязательность роли | Нет |
| Ограничения значения | До 5 000 символов; пустое значение допустимо |

### 4.8. Роль `TAGS`

| Свойство | Значение |
|---|---|
| Поле `Task` | `tags` |
| Тип | Список строк |
| Обязательность роли | Нет |
| Ограничения значения | До 10 значений; каждое значение 1–50 символов; разделитель `;` |

### 4.9. Роль `ATTRIBUTE`

`ATTRIBUTE` — произвольная дополнительная характеристика задачи.

| Свойство | Значение |
|---|---|
| Поле `Task` | Расширяемая характеристика задачи |
| Тип | Определяется правилами конкретной характеристики |
| Обязательность роли | Нет |
| Ограничения значения | Не ограничиваются универсальным справочником |

**Правила:**

- Пользователь может создать произвольное количество именованных дополнительных характеристик.
-Каждой характеристике назначается одна или несколько колонок исходного CSV.
- Названия характеристик не образуют заранее заданный системный справочник.
- Примеры характеристик: компоненты, затронутые сценарии, модуль, тип работы, заказчик.
- `Компоненты` и `Задетые сценарии` из прежней версии спецификации являются примерами таких характеристик, а не обязательными полями Planning Poker.
- Система сохраняет исходное значение характеристики; универсальные преобразования значений не применяются.
- В будущем характеристики могут сопоставляться с одноимёнными колонками загруженной базы исторических эталонов и использоваться как дополнительные признаки сравнения.
- Сопоставление с эталонами, рекомендации и возможная платность — направления развития, а не требования текущего импорта.

## 5. Шкала Story Points

Поддерживаемая шкала для первого спринта:

```text
0, 0.5, 1, 2, 3, 5, 8, 13, 20, 40, 100
```

**Правила:**

- Шкала применяется к значениям колонки с ролью `FINAL_SP_TARGET`.
- Пустое значение в этой колонке допустимо при импорте.
- Значение должно точно соответствовать допустимой шкале, если оно указано.
- Старые значения в колонке `FINAL_SP_TARGET` не используются как исходные оценки.
- `initialStoryPoints` не является обязательным полем импорта и не используется в текущем сценарии оценки.

## 6. Нормализация значений

Нормализация зависит от типа данных, назначенного колонке.

| Тип данных | Правила нормализации |
|---|---|
| Краткая строка: ID, заголовок, приоритет, простое значение характеристики | Удалить пробелы в начале и конце значения |
| Многострочный текст: описание, комментарии | Сохранить значимое форматирование, включая переносы строк и отступы; удалить пробелы только в начале и конце всего значения |
| URL | Удалить пробелы в начале и конце; проверить схему `http://` или `https://` |
| Список: теги | Разделить значение по `;`, удалить пробелы у каждого элемента, удалить пустые элементы |
| SP | Удалить пробелы в начале и конце; проверить соответствие шкале |
| Дополнительная характеристика | Сохранить исходное значение без автоматического изменения регистра или подстановки значений |

**Правила:**

- Пустая строка или строка из пробелов считается пустым значением.
- Пустые элементы после разделения списка удаляются.
- Для произвольных характеристик не применяются универсальные преобразования вида `api → API` или `заказ → ЗАКАЗ`.
- Неизвестные значения не преобразуются автоматически, если для них не согласованы отдельные правила.

## 7. Валидация

### 7.1. Валидация разметки

Импорт блокируется до проверки строк, если:

- файл не выбран;
- файл не читается;
- файл пустой;
- файл содержит только заголовки;
- структура CSV некорректна и файл не может быть разобран;
- кодировка не UTF-8;
- количество задач превышает лимит;
- размер файла превышает лимит;
- не назначена роль `TASK_ID`;
- не назначена роль `TITLE`;
- не назначена роль `FINAL_SP_TARGET`;
- одна обязательная роль назначена более чем одной колонке;
- одна колонка назначена более чем одной роли.

### 7.2. Валидация строк

После успешной разметки система проверяет **все строки**, подлежащие обработке. Валидация не останавливается на первой ошибке.

| Ситуация | Тип реакции |
|---|---|
| Пустое значение в колонке `TASK_ID` | Ошибка строки |
| Дубликат значения `TASK_ID` в файле | Ошибка второй и последующих строк с этим ID |
| Пустое значение в колонке `TITLE` | Ошибка строки |
| Превышен лимит символов `TITLE` | Ошибка строки |
| Некорректное значение в колонке `YOUTRACK_URL` | Ошибка строки |
| Некорректное значение SP в колонке `FINAL_SP_TARGET` | Ошибка строки |
| Превышен лимит символов `DESCRIPTION` | Ошибка строки |
| Превышен лимит символов `NOTES` | Ошибка строки |
| Некорректное значение в колонке `TAGS` | Ошибка строки |
| Некорректное значение обязательной характеристики | Ошибка строки, если такие правила заданы |
| Лишняя колонка без назначенной роли | Не ошибка |
| Отсутствующая необязательная колонка | Не ошибка и не предупреждение |

Для каждой ошибочной строки отображаются:

- номер строки в исходном файле;
- назначенная роль или название характеристики;
- описание ошибки.

Отображение исходного значения и имени исходной колонки может дополнительно помогать пользователю, но не является обязательным требованием.

### 7.3. Дубликаты ID

- Первая строка с уникальным ID остаётся корректной, если она проходит остальные проверки.
- Вторая и последующие строки с тем же ID помечаются ошибкой.
- Ошибочные строки не импортируются.

## 8. Стратегия обработки ошибок

Для первой версии используется импорт всех успешно прошедших проверку строк с явным подтверждением.

### 8.1. Правила

1. Пользователь выбирает один CSV-файл.
2. Система разбирает структуру файла и показывает реальные заголовки колонок.
3. Пользователь назначает обязательные и при необходимости необязательные роли.
4. Система проверяет разметку и все строки файла.
5. В предпросмотре отображаются корректные задачи.
6. Для ошибочных строк отображаются номер строки и причина ошибки.
7. Host может импортировать только корректные строки.
8. Ошибочные строки не добавляются в очередь.
9. Host видит количество корректных и ошибочных задач.
10. Если есть хотя бы одна корректная задача, импорт доступен.
11. Если корректных задач нет, импорт недоступен.
12. Отмена импорта не изменяет текущую очередь задач.

«Выборочный импорт» означает импорт **всех корректных строк**, а не ручной выбор отдельных задач пользователем. Отдельный интерфейс редактирования ошибочных строк в предпросмотре не требуется.

### 8.2. Состояния предпросмотра

| Состояние | Условие | Действие |
|---|---|---|
| Разметка не завершена | Не назначена хотя бы одна обязательная роль | Импорт недоступен |
| Все строки корректны | Ошибок нет | Кнопка «Импортировать N задач» |
| Есть ошибки | Есть корректные и ошибочные строки | Кнопка «Импортировать N корректных задач» |
| Все строки с ошибками | Корректных строк нет | Импорт недоступен |
| Файл невалиден | Ошибка уровня файла или разметки | Импорт недоступен, показывается общая ошибка |

### 8.3. Ручное создание задачи

В рамках сценария нельзя загрузить несколько CSV-файлов. В процессе работы может быть доступно отдельное ручное создание задачи по обязательным полям.

Эта операция отличается от импорта второго файла. Правила добавления такой задачи в существующую очередь и изменения API должны быть согласованы отдельно. Ручное создание задачи не даёт права автоматически менять или переставлять очередь.

## 9. Пример разметки

Исходный CSV может иметь произвольные заголовки:

```csv
"Key","Summary","Details","Issue URL","Team Priority","Actual Estimate","Module","Business Flow","Comments","Labels"
"TASK-1111","Добавить фильтр заказов","Реализовать фильтрацию списка заказов по статусу.","[https://youtrack.example/issue/TASK-1111](https://youtrack.example/issue/TASK-1111)","High","","API;WEB","ЗАКАЗ","Учесть права доступа.","backend;ux"
"TASK-3333","Исправить ввод даты","Исправить некорректную валидацию даты в форме ввода.","[https://youtrack.example/issue/TASK-3333](https://youtrack.example/issue/TASK-3333)","Medium","","WEB","ВВОД","-","frontend"
```

Возможная разметка пользователя:

| Колонка CSV | Назначенная роль |
|---|---|
| `Key` | `TASK_ID` |
| `Summary` | `TITLE` |
| `Actual Estimate` | `FINAL_SP_TARGET` |
| `Details` | `DESCRIPTION` |
| `Issue URL` | `YOUTRACK_URL` |
| `Team Priority` | `PRIORITY` |
| `Comments` | `NOTES` |
| `Labels` | `TAGS` |
| `Module` | `ATTRIBUTE`: «Компонент» |
| `Business Flow` | `ATTRIBUTE`: «Затронутый сценарий» |

В этом примере колонка `Actual Estimate` может уже содержать старые значения. Они игнорируются при импорте; в дальнейшем в эту колонку могут быть записаны итоговые SP.

## 10. Обязательные тестовые файлы

| № | Файл | Назначение |
|---|---|---|

| 3 | `custom-attributes.csv` | Дополнительные пользовательские характеристики |
| 4 | `empty-file.csv` | Проверка пустого файла |
| 5 | `headers-only.csv` | Проверка файла без задач |
| 6 | `invalid-structure.csv` | Некорректная структура CSV |
| 7 | `row-errors.csv` | Ошибки в отдельных строках |
| 8 | `duplicate-ids.csv` | Дубликаты ID; ошибка у второй и последующих строк |
| 9 | `mixed-results.csv` | Корректные и ошибочные строки в одном файле |
| 10 | `no-final-sp-column.csv` | Отсутствует колонка для итоговых SP |
| 11 | `existing-final-sp-values.csv` | В колонке итоговых SP уже есть значения |
| 12 | `youtrack-export.csv` | Проверка совместимости с экспортом YouTrack |

Тестовые файлы должны проверять не только синтаксис CSV, но и продуктовое решение: разные языки и имена колонок, кастомные характеристики, три обязательные роли, отсутствие необязательных полей без предупреждений, дубликаты ID, смешанные корректные и ошибочные строки, однофайловый сценарий и предупреждение о замене существующих значений итоговых SP.
