# Planning Poker

Веб-приложение для командной оценки трудоёмкости задач (Planning Poker).

> Статус: **подготовка репозитория**. Код клиента и сервера, команды запуска, CI/CD и развёртывание будут добавляться отдельными задачами. Наличие структуры файлов не означает готовность приложения.

## Первичная публикация

Этот комплект можно скопировать **в корень уже клонированного GitHub-репозитория**. В комплекте нет `.git/` или скриптов повторного создания репозитория. Пошаговая инструкция по первой публикации, созданию `develop`, защите веток и приглашению команды: [`docs/SETUP_GITHUB.md`](docs/SETUP_GITHUB.md).

## Схема веток

```text
                 feat/... ─┐
 develop ──────────────────┴─> PR + review + Squash and merge ─> develop
     │
     └─────────────────────────> PR принятого релиза ─> main (merge commit)
```

- `main` — принятые релизы, не место для незавершённой разработки.
- `develop` — общая рабочая ветка (должна оставаться собираемой после появления приложения).
- `feat/...`, `fix/...`, `refactor/...`, `docs/...`, `test/...`, `chore/...` — временные ветки от актуальной `develop`.
- В `develop` — только через PR с одобрением другого разработчика и **Squash and merge**.
- В `main` — только утверждённые тимлидом релизы, через PR; способ объединения между постоянными ветками — **Create a merge commit**.
- Исключительные `hotfix/...` создаются от `main`, затем изменения обязательно переносятся в `develop`.

## Локальное окружение

Технологический стек и инструкции запуска пока не согласованы. Ответственные разработчики внесут команды запуска в README соответствующих каталогов.

Реальные `.env` файлы, токены, приватные ключи и пароли не добавлять. `.env.example` — пустой безопасный шаблон для дальнейшей конкретизации.
