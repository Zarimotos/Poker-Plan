# Planning Poker

Веб-приложение для командной оценки трудоёмкости задач в Story Points. Команда проводит сессию, оценивает задачи, фиксирует итоговые значения и получает результаты.

> **Текущее состояние:** подготовительный этап завершён; команда переходит к реализации первого рабочего пользовательского сценария. В ветке `develop` пока нет готового к запуску приложения. Наличие каталогов `frontend/` и `backend/` не означает, что клиент и сервер уже реализованы.

## Проектные документы

У проекта три основных документа. Каждый отвечает на отдельный вопрос:

| Документ | Вопрос | Содержание |
|---|---|---|
| [Продуктовый анализ](docs/product-analysis.md) | **Что делаем?** | Наполнение спринтов: задачи, ожидаемые результаты, границы и возможность переноса. |
| [План итеративной разработки](docs/iteration-process.md) | **Как работаем?** | Вертикальные срезы, L1–L3, DoR/DoD, организация проверок, Git, PR и релизы. |
| [Дорожная карта](docs/roadmap.md) | **Когда и куда?** | Контрольные точки и ожидаемое состояние продукта к каждой из них. |

**Ближайшая продуктовая цель:** один Host создаёт серверную сессию, загружает CSV с пользовательским назначением колонок, видит очередь, оценивает задачи, подтверждает Story Points и получает сохранённые итоги. Подключение участников, поиск эталонов и экспорт относятся к последующим этапам.

## Структура репозитория

- [`frontend/`](frontend/) — клиентское приложение; структура и инструкция запуска появятся вместе с реализацией.
- [`backend/`](backend/) — серверное приложение; структура и инструкция запуска появятся вместе с реализацией.
- [`docs/specs/`](docs/specs/) — подготовленные спецификации и предложения технических решений. Они служат исходным материалом: детали реализации могут уточняться командой в ходе разработки при сохранении продуктовых требований.
- [`docs/tasks/sprint-0/`](docs/tasks/sprint-0/) — материалы завершённого подготовительного этапа.
- [`docs/design.md`](docs/design.md) — сведения о дизайне и ссылка на актуальный макет, когда она будет внесена.
- [`CONTRIBUTING.md`](CONTRIBUTING.md) — краткая памятка о внесении изменений и ревью.
- [`docs/SETUP_GITHUB.md`](docs/SETUP_GITHUB.md) — историческая инструкция первоначальной настройки GitHub.

## Работа с репозиторием

- `develop` — ветка совместной интеграции изменений.
- `main` — только принятые релизы.
- Работа ведётся в отдельных ветках от `develop`; включение изменений — через Pull Request с ревью.
- Общие правила работы и выпуска версий описаны в [плане итеративной разработки](docs/iteration-process.md); практические шаги для PR — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Запуск приложения

Инструкций запуска пока нет, так как в `develop` ещё не опубликована работающая реализация. После появления клиента и сервера разработчики добавят необходимые команды, зависимости и примеры конфигурации рядом с соответствующим кодом.

**Безопасность:** не добавляйте в Git настоящие пароли, токены, ключи и файлы `.env` с секретами. Для необходимых параметров используйте безопасные примеры `.env.example`.
